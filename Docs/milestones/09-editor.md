## Shared project snapshot

Add `project.check_snapshot(paths=None, *, root=None, audit=False, target=TARGET, cache=True, overlays=None) -> ProjectSnapshot`. An overlay is an exact `{absolute_existing_python_path: {"text": decoded_source_text, "version": integer}}` mapping. It is read-only: the engine never writes source/policy or imports application modules. Existing `check_paths` remains compatible and returns its existing `ProjectResult` through the same underlying pipeline. The captured graph uses actual policy validation, supported runtime gate, project path discovery, local package/module precedence, transitive import closure, source writer context, installed integration identities/approval expiry, failure/effect propagation and guard selection. A standalone `analyze_source` result never establishes editor evidence.

`ProjectSnapshot` contains `result: ProjectResult`, `sources: dict[path,text]`, `inputs: dict`, `freshness: str`, `snapshot: str`, and an internal captured graph for conservative resolved navigation. `inputs` is serializable and contains `sources` rows `{sha256, origin: "disk"|"overlay", version: int|null, disk_sha256}`, `policy_sha256` (including absent-policy identity), `product_artifacts`, relevant `integration_inputs` and requested `paths`, `root`, `audit`, `target`. `snapshot` is SHA-256 of canonical JSON of these inputs. Source text is separate from normal CLI report output. `freshness` is `"current disk snapshot"`, `"current overlay snapshot; unsaved"`, or `"stale; recheck required"`; it is not a runtime certificate.

The source loader accepts supplied decoded overlays when a selected/dependency path is read, preserving normal Python declared encoding through explicit encoding/decoding validation. Every open buffer in the root is supplied, including imported dependencies. An overlay file must already exist as a `.py` file under the root; new untitled/outside-project files are unsupported rather than promoted through incomplete resolution. Server analysis selects the root to retain ordinary analyzed writers and cross-file policy coverage. Canonical ownership of selected/transitive source and policy is checked before content reads, including symlink targets. Relevant disk sources, policy bytes, product identities and integration snapshot are recaptured before publication. The server captures startup product identities and refuses all current project/file claims after an on-disk product mismatch until restart. Server observations and previews use `cache=False`, so a loaded older implementation cannot publish body caches under new disk hashes; existing CLI and optional shared-API caching retain their behavior. This editor version makes no incremental-body-reuse claim. Concurrent changes produce a tooling diagnostic, mark contracts unverified/stale, and publish no current successful claim. Unsaved overlays are explicitly identified and never become a checked-build artifact or durable disk certificate. Closing a document restores disk analysis. The serialized server prevents simultaneous document mutations during a request; monotonic document versions reject delayed replacement buffers.

## Authored locations

Add optional `Diagnostic.end_line`/`end_column` fields, defaulting to `None`, and `column_encoding` defaulting to `"utf-8-bytes"`, so historical/cache records deserialize unchanged. Static AST diagnostics carry one-based line and UTF-8-byte columns at both ends; end is exclusive. Tokenize-produced directive locations use `"unicode-codepoints"` metadata because tokenize columns count decoded characters. SyntaxError-produced offsets also count code points; existing point fallback start fields remain compatible and their encoding is explicit. Existing CLI rule, start path/line/column, affected boundary, origin, reason, remediation and first-binding fields remain identical. Syntax/tooling diagnostics without an AST span use a visible point/line fallback and disclose that no precise span is available. The server converts each producer's coordinates to decoded text, then zero-based UTF-16 LSP positions, including non-ASCII and astral characters and LF, CRLF or lone-CR physical source lines. Unicode separators within string content do not create authored lines. It never counts UTF-8 bytes as editor character units. First-binding related locations retain the same authored path/line. Source navigation returns original authored URIs and ranges.

`textDocument/publishDiagnostics` uses the actual engine diagnostic rule as `code`, source `"pyalamode"`, severity 1 for strict/tooling failures or 2 for audit findings, and message `reason + "\n" + remediation`. Its `data` has `{boundary,origin,reason,remediation,authored:{path,line,column,end_line,end_column,column_encoding},snapshot,version,diagnosticIndex}`. `relatedInformation` contains a first-binding location when available. Each publication includes `uri` and the current open-buffer `version` (omitted for closed documents). Removed/closed/deleted findings are explicitly cleared. Tooling diagnostics from policy/project paths are published at those authored paths and remain visible in the project response; they are never converted into a clean check.

## Wire protocol and launch

Launch with `<literal environment python> -I -m pyalamode.editor --stdio --root /absolute/project`, after installing Pyalamode into that interpreter's environment. Use the explicitly configured interpreter, including literal `.venv/bin/python`; never resolve its symlink to a base interpreter. Python isolation excludes the workspace/current directory and `PYTHONPATH` from startup module resolution, so authored workspace packages cannot replace/evaluate the server before its static checking boundary. The environment's installed startup machinery remains an execution precondition. The installed console command `pyalamode editor --stdio --root /absolute/project` remains available under ordinary Python startup assumptions and adds no interpreter isolation. Plain `python -m pyalamode.editor` from an authored workspace is not a nonexecution launch guarantee. Transport is local stdin/stdout only, using LSP-style ASCII `Content-Length: <UTF-8 bytes>\r\n\r\n` headers and UTF-8 JSON-RPC 2.0 bodies. A supplied Content-Type must name UTF-8; unsupported content encodings error. No socket, network service, shell expansion or application evaluation is used. Stdout contains protocol frames only; bounded tooling logs go to stderr. Maximum body size is 8 MiB and header size is bounded separately. Invalid UTF-8/JSON in a complete known-length frame, invalid params, unknown methods and lifecycle errors return bounded protocol errors without executing source, and leave the process usable. Malformed/duplicate/missing/nondecimal/oversize Content-Length or non-ASCII/oversize headers terminate after a bounded framing error; the server never guesses the next frame boundary. Unsupported Content-Type in a known-length frame consumes that bounded body and errors recoverably. EOF/truncated frames end the process. Notifications receive no JSON-RPC response. Initialize precedes requests; shutdown disables work; exit ends the process. This finite transport follows the [LSP 3.17 specification](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/specification.md).

`initialize` accepts `rootUri` matching the launch root and returns `capabilities` with `positionEncoding:"utf-16"`, `textDocumentSync:{openClose:true,change:1,save:{includeText:false}}`, `hoverProvider:true`, `definitionProvider:true`, `referencesProvider:true`, `documentSymbolProvider:true`, `codeActionProvider:true`, and `serverInfo:{name:"pyalamode",version:<checker version>}`. `capabilities.experimental.pyalamode` is `{schema:1,target,pythonExecutable:sys.executable,pythonVersion:[major,minor,patch],platform,root,filesystemEncoding,filesystemErrors}` using builtin observed metadata without config/import hooks. The client records its literal configured launch path separately, preserving `.venv/bin/python` symlink semantics. Header size is at most 8 KiB; body size is at most 8 MiB. The supported standard messages are `initialized`, `shutdown`, `exit`, `textDocument/didOpen`, `didChange` (one full-text content change, monotonic version), `didClose`, `didSave`, `hover`, `definition`, `references`, `documentSymbol`, and `codeAction`. Only local `file:` URIs without a remote authority are accepted; decoded paths are canonicalized and checked against the root. Configuration/permission/trust updates and source-write requests are unsupported. `$/cancelRequest` can be ignored because analysis is serialized and bounded; no false cancellation guarantee is advertised.

Standard requests use LSP parameter shapes and zero-based UTF-16 positions/ranges. `hover` returns `Hover|null` with markdown describing the engine's containing participating boundary and relevant inferred binding schema, including enforcement, source evidence/freshness, declared/required effects and origins, transitive assumptions, invocation/definition failures, ordinary initialization and guard coverage. It labels unverified contracts visibly. `documentSymbol` returns LSP `DocumentSymbol[]` for selected functions (including nested), records/variants and explicitly unsafe ordinary adapters, preserving authored ranges. `definition` and `references` return `Location[]` only for participating declarations and actual direct checked-call occurrences established by the engine's per-call failure edges; local parameters/shadowed/unknown/dynamic calls do not receive guessed targets. Foundation/external operation evidence appears in hover/explanations, without invented local source definitions. This finite navigation contract is smaller than a general Python type checker.

## Program-change preview rules

Previews never add effects/permissions, trust, suppressions, ignores, source selection, guard settings, snapshot conversions, imports, annotations, handlers, or changed failure behavior. They never write source. Every preview includes its unchanged input snapshot and rechecks the candidate through the complete project engine with a temporary overlay; remaining diagnostics and unsupported preconditions remain explicit.

Two bounded cases are implemented. For `PAL250`, an expression-statement persistent update can become `updated_value = <identical expression>` with a fresh unused function-local name. Eligibility requires a direct function-body statement, recognized engine PAL250, no nested function/class, reflection/dynamic-name/unknown operation diagnostics or scope-changing constructs, and no colliding identifier anywhere in that function. The original update expression evaluates once in its existing order with its existing operands and failures; its immutable returned value is bound without changing subsequent admitted expressions. The diff does not pretend to update the old collection or rewrite callers. Its usefulness is primarily to make the retained new value visible for a user's next edit.

For `PAL101`, a second simple `name = expression` in a straight-line participating function can become a fresh `name_2` binding, with subsequent lexical reads renamed. Eligibility is deliberately closed: exactly two assignments to that non-parameter local; only direct body `Assign`/`AnnAssign` with one Name target, `Return`, `Pass` and optional docstring; the final Return is the only terminating statement; no branch/loop/handler/match/with/import/global/nonlocal/walrus/del/augassign, nested definition, lambda/comprehension, callback/capability/capture/returned-callable or alias evidence; no unknown/unsupported/dynamic-name diagnostics beyond this one reassignment; no attributes/subscripts used as writes; no same-name use in annotations/defaults/decorators. All remaining operations are established exact admitted scalar/tuple/product-data operations with no callbacks or capabilities. The second assignment RHS continues to read the first binding; only that target and later reads use the fresh name. This preserves the ordinary original data flow, order and characterized failure behavior for contract-satisfying inputs, without requiring source execution. The candidate must pass a strict full-project check, with unchanged retained trust/effect/failure/operation dimensions, or the server refuses the preview. The original invalid contract remains visibly unverified; comparing retained dimensions does not promote its behavior to a checked claim. More general SSA/control-flow conversion is M10-or-later design work and is not claimed here.

All previews disclose that supported execution assumptions still apply and that naming choice and usefulness require user judgment. A missing safe preview leaves the shared explanation/remediation available; the server never manufactures a permission-changing repair.
