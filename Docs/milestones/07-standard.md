## Version, identity and shared conditions

The proposed catalog is `pyalamode.standard-v1`, on CPython 3.13.1 standard GIL builds on macOS and Linux with native filesystem encoding utf-8 and errors surrogateescape. Every name below resolves to the unchanged product export or `pyalamode.standard` operation, not a familiar spelling, arbitrary method, imported declaration or annotation. Product fingerprints include actual `standard.py`, a static-only `standard_contracts.py` catalog and all inherited product files. Operations are trusted product foundations with a closed inventory of actual native/stdlib and product helper reads, explicit input/output/effect/failure/initialization/alias fields and version provenance. They are not source-checked application implementations or an external integration approval. M8 approval mechanisms remain deferred.

All new call signatures use exactly the positional-only arguments shown; no keywords, star arguments, iterables, lazy execution or dynamic options. Data means the inherited recursively exact scalar/tuple/collection/record/closed-case domain. Scalar subclasses and foreign protocols are refused. Invalid ordinary inputs raise `TypeError` without running their getters, operators, iterators, formatters or restoration hooks; those ordinary validation failures are distinct from failures under valid admitted inputs. Resource exhaustion and interruption retain the inherited limits.

Product module initialization defines functions and imports already characterized product/type foundations and exact native scalar arithmetic/Unicode failure constructors. It observes no time, environment, random data or filesystem values and runs no application callback. Pure invocation evidence does not certify ordinary application import initialization. Ordinary provider setup and later effectful invocation are separately described below and in per-file setup observations. Arbitrary ordinary initialization stays unchecked, even when a finite recognized setup call is described.

## Eager functional toolkit

These operations accept actual resolved checked callable evidence, including every finite conditional alternative and its stable captures. Exact ordinary Python `FunctionType` runtime validation establishes callable representation only; annotations/decorators do not establish purity. A callback cannot have unknown targets, changing captures or retained capabilities. Invocation propagates target operations, failures, trust and declared/required effects. A declared effect alone never authorizes an unknown operation. All callback parameters/results require exact established signatures before admission.

| Identity (all `standard-v1`) | Exact signature and order | Result and failure behavior | Aliases / cost |
| --- | --- | --- | --- |
| existing `Vector.fold` | `(callback:(A,T)->A, initial:A, /)->A` on ordered `Vector[T]` | Left-to-right, once per item, initial returned for empty input; callback failures/effects propagate. | Immutable stable accumulator; eager O(n) callbacks plus callback/validation cost. Existing M3 semantics are retained and cataloged. |
| `vector_scan` | `(values:Vector[T], callback:(A,T)->A, initial:A, /)->Vector[A]` | Initial is first output, then every successive accumulator in input order; n+1 outputs, n callbacks; stops immediately on a failure. | Stable data retained by value; O(n) storage/callbacks plus nested validation. |
| `vector_group_by` | `(values:Vector[T], callback:T->K, /)->OrderedMap[K,Vector[T]]`, K one homogeneous exact scalar schema | Once per item in input order; group keys appear in first-encounter order and each group preserves input order. | No unordered traversal/history leak; eager tuple-backed grouping may be O(n²) key comparisons/copies plus callbacks, O(n) retained data references. |
| `compose` | `(outer:(B)->R, inner:(A)->B, /)->(A)->R` | Construction invokes neither callback. Invocation calls inner once, then outer once if inner completes; outer is skipped on inner failure. A may be an exact capability slot with the corresponding bound, B/R admitted data; effects/failures union at invocation. | Retains exact callbacks and their stable captures; O(1) wrapper construction, fixed two calls per invocation. No runtime callable registry. |
| `partial_first` | `(callback:(A,B)->R, bound:A, /)->(B)->R`, A and R admitted stable data | Construction validates and retains bound but does not invoke callback. Invocation calls callback once with bound first and supplied second; B may be a supported capability slot. | Never binds/retains a capability, callback or unknown foreign argument as A; stable captures and target evidence preserved, O(1) wrapper plus nested bound validation. |
| `result_traverse` | `(values:Vector[T], callback:T->Result[U,E], /)->Result[Vector[U],E]` | Left-to-right fail-fast: invoke once per visited item, return the first Err unchanged in meaning, skip subsequent callbacks; all Ok produces an ordered Vector, empty input produces Ok(empty). | Exact Ok/Err only, no iterator or restoration; O(n) callbacks/storage plus nested validation; callback raised failures and effects remain visible separately from E data. |

The inferred returned wrapper schema is fixed, including the union of finite callback effect bounds. Static wrapper evidence records nested operation identity, actual underlying targets, captures and bound data schemas; it survives returned/retained/captured/cold/full-warm/partial-warm flows. Checked factory calls specialize returned wrapper callback obligations with the actual supplied callable evidence; finite conditional wrapper choices retain every component and never reuse a leaf function signature as the wrapper invocation signature. Wrapper construction records dependency/trust assumptions but no invocation effects or callback failures. Invocation records the actual target edges with each occurrence's inherited failure mask. Wrappers can be callbacks to inherited Vector map/filter/fold and new operations, but cannot be data payloads or guarded callable exports. General variadic partial, currying, arbitrary composition arity and generic application inference remain outside this catalog.

New eager callbacks/wrapper construction are confined to checked function bodies. New scalar operations may be used in functional module initialization/stable defaults because their exact pure initialization behavior and fixed failures are published; checked application callbacks and provider construction remain refused there. No hidden execution is introduced by check/build.

## Filesystem, clock and environment, including setup

The existing `effects-v1` exact interfaces gain `standard-v1` catalog entries while retaining M5 behavior, full-interface capability parameters, finite policy bounds and lexical lease rules. `IOCapability.read_text(path:str,/)->str` / `write_text(path:str,text:str,/)->None` require IO; use rooted whole-file bytes with the new manual strict UTF-8 conversion and newline preservation, internal binary open/read-or-write/close on every path, declared read/write permissions, no symlink components under published filesystem stability/TOCTOU preconditions. Caller-supplied roots/relative paths/environment names reject every surrogate code point before native OS conversion. Failures: OSError, UnicodeError, ValueError, RuntimeError, KeyError. `ClockCapability.now_ns(/)->int` requires Clock, uses time.time_ns for live providers or consumes recorded values; failures RuntimeError/OSError/IndexError. `EnvironmentCapability.get(name:str,default:str,/)->str` requires Environment, accepts a nonempty exact name without `=`/NUL; failures RuntimeError/ValueError/OSError/UnicodeError. Controlled providers retain the same effects. Invalid UTF-8 cannot call the mutable registered Python error handler. Live write opens/truncates the target before encoding, retaining inherited non-atomic failure semantics: UnicodeError can leave an empty/truncated file; partial writes or OS failures are not rolled back. No new arbitrary OS or native API is admitted.

`live_io(root:str,*,allowed_ops:tuple[str,...])` is ordinary setup that requires the supported UTF-8 filesystem condition, rejects surrogate root code points, resolves/checks an existing root through realpath/isdir and thus observes IO, independently of later read/write. Provider object creation by `live_clock()` and `live_environment()` does not sample time/environment; live_environment checks the supported native filesystem condition. Live IO/environment setup raises RuntimeError outside that condition. Subsequent invocation has Clock/Environment. Native UTF-8/surrogateescape environment-value decoding retains exact low-surrogate escapes for invalid high bytes without calling a registered replacement handler; name input restrictions are separate from returned values. Recorded provider construction validates explicit tuples and allocates private mutable provider storage; subsequent interface effects remain. All setup remains ordinary unchecked source: recognized setup observations publish known operation/effect/failure/input identities and explicitly say they do not characterize surrounding module initialization. Strict modules cannot import an ordinary setup module merely because one exported function is pure. Pure imported exports in ordinary modules retain separate per-file unchecked initialization evidence.
