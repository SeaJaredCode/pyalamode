## Finite value and callable contract

Scalars keep M1's exact `int`, `bool`, `str`, `bytes`, and `None` domains, excluding subclasses. Annotations include stable `types.NoneType` imports, `types.NoneType`, stable `builtins` scalar/tuple attributes, and supported quoted expressions. The annotation parser is a finite source interpreter; it does not call Python typing machinery.

Tuples use fixed `tuple[T1, T2]`, homogeneous `tuple[T, ...]`, or empty `tuple[()]`. Components recursively have admitted data schemas. A fixed tuple can meet a homogeneous tuple obligation when every element meets its schema; a homogeneous parameter cannot establish a fixed length. Construction and `len` are admitted. Mutable nested members, subclasses, tuple unpacking, callable/module payloads, arbitrary protocols, `Any`, unions, tuple indexing/slicing/comparison, and iteration are excluded. Tuple order and recursively exact component types participate in the value contract; arbitrary equality does not define equivalence.

Callables use a stable `typing` or `collections.abc` import of `Callable`, including import/module aliases, with `Callable[[T1, T2], R]`. Arguments/results can themselves have supported callable contracts. The signature has exactly the listed positional arguments, admitted exact result, pure invocation, and stable captures. Ellipsis, `Any`, protocols, variadics, and keyword-only callback targets are excluded. Positional-only targets and optional positional defaults qualify when invocation with the complete fixed positional sequence fits. Direct checked calls additionally support ordinary keyword-only/positional-only arguments and stable omitted defaults according to their actual declared signature.

A callable annotation states an input obligation; it never promotes an actual unknown function to pure evidence. Checked callers establish a resolved checked target/captures or pass an admitted callable input from their own contract. Ordinary parameters, even annotated `Callable`, remain unknown at inspected calls. Anonymous lambdas and builtin callbacks are excluded; characterized builtins remain direct operation calls.

Conditional callable invocation has the finite upper failure bound `{ZeroDivisionError, RecursionError}`, the current complete supported callable failure universe. That bound propagates through callback parameters/defaults and nested/returned callable contracts. Concrete known returned targets preserve their metadata and precise failures. Direct invocation graphs propagate failures across recursive components and callers. Recursion has no termination promise; `RecursionError` is characterized, while process interruption/resource exhaustion are outside the contract. Default-expression failures and functional-module initialization failures are separate fields; importing a functional dependency propagates its known initialization failures.

## Selection, bindings, and initialization

`# mode: fun` occurs once at column zero after the optional shebang, encoding declaration, and existing module docstring, before the first executable statement. String contents do not become directives. A misplaced marker, duplicate marker, or reserved `# mode:` region toggle fails `PAL121`. Module mode selects definitions and source initialization. `require_modules` accepts nonempty project-relative case-sensitive glob strings, including `**/` matching zero directories; absolute paths, parent traversal, backslashes, and non-string entries are tooling/policy failures. Required mode works without source markers and cannot be weakened by source toggles.

In an ordinary module, a resolved unchanged `@fun` selects that function and its nested definitions. In module mode, a marker is optional. The only admitted decorator is one resolved `pyalamode.fun` identity declaration; additional decorators, called markers, class-bound functions, async/variadic/generic definitions, and declaration hooks fail. Marker and annotation names are resolved with their lexical scopes and definition-site availability. Lexical type-name shadows remain shadows across multiple nesting levels. Quoted/postponed annotations are parsed without hooks; unsupported alias schemes still fail closed.

A source constant qualifies through one characterized immutable initialization, actual resolution, and no analyzed writer. It need not have upper-case spelling or live in a functional module. A global object's current runtime type, `Final`, hashability, or an ordinary annotation alone does not qualify it. Earlier stable references and the closed scalar/tuple operations can establish values; forward/cyclic initializer references are unknown. Unrelated ordinary initialization remains unchecked.

A selected enclosing function supplies exact parameter/local schemas and stable callable captures. Nested functions can shadow names in actual lexical scopes. Stable captures travel across multiple checked nesting levels; the report records used captures, including those needed by returned closures. A changed enclosing binding, `nonlocal` writer, unknown ordinary parameter, or uncertain outer cell blocks admission. Stable literal locals from a directly enclosing ordinary function can qualify, provided all analyzed writes are ruled out. More distant ordinary captures are rejected conservatively rather than resolved to a familiar global name.

Sibling checked signatures are available for mutual recursion, but predeclaration is not runtime initialization. Every required closure cell must be initialized before the callable is invoked or returned. Calling one sibling before its dependency definition, or returning it before an unreachable sibling definition, fails. Body calls, argument passing, and return contracts use resolved callable evidence, not a function spelling.

Module initialization/default expressions use stable admitted values, earlier bindings, tuple construction, characterized scalar operations, approved builtins, and checked callable references. **Checked application function invocation in initialization/default expressions is deliberately excluded from this finite M2 increment.** Defaults containing mutable values, unknown hooks, forward/self references, or wrong schemas fail without execution. Module-level imports, checked definitions, supported one-name initialization, admitted conditional initialization, docstrings, and `pass` are checked; unknown statements/class bodies/import setup fail. Only supported decorator/annotation syntax qualifies. Arithmetic initialization/default failures remain separately characterized, rather than falsely attached to an independent function invocation.

## Source resolution and freshness

Local source resolution uses only the project-root source tree: normal absolute and relative imports, `module.py`, and initialized packages. An initialized package wins over an identically named `.py` module, matching CPython's finder. A module file cannot serve as a package for a dotted import. Package initializer source participates in initialization/freshness assumptions. Unsupported namespace/import layouts and external packages remain unresolved; there is no user import or installed-package execution fallback. Aliased imports and module-attribute calls resolve the actual source target.

Strict modules import characterized foundations or functional local modules. A checked function in an ordinary module can call a source-checked export from another ordinary module; both modules' initialization remain expressly unchecked. The ordinary shell may initialize those modules before pure invocation. Missing exports, unknown setup, participating dependency violations, and analyzed replacements fail the selected gate. A local `pyalamode`, `typing`, `types`, or `collections` implementation cannot acquire trusted behavior through its name. The actual installed product initializer is recognized by its concrete path/product bytes.

Recognized analyzed namespace/attribute writers, global statements, setters, aliases, function `__code__`/defaults/namespace modifications, and foundation callable/annotation-object modifications undermine relevant binding evidence. Cross-file ordinary writers are part of this context when those files are selected or loaded. Ordinary source outside the analyzed graph remains an unchanged-dependency execution assumption. This is source verification rather than hostile-Python isolation, complete dynamic alias inference, or a live process monitor.

Project fingerprints include exact captured source bytes/path, edition/rule/operation/target/platform/policy/product identities, transitive local import bytes/resolution paths, and relevant analyzed replacement identities. Adding an ordinary writer can invalidate a referenced function or foundation even when no caller/imported file changed. Adding a local foundation shadow changes resolution and keys. Per-file cached body evidence is reused only under the same current context; discovery, signatures, identities, and binding context are reconstructed from the current snapshot. Concrete cached callable targets/capture schemas are restored so losing cache precision cannot erase known behavior.

Invalidation follows conservative source import closures: unrelated modules can retain hits, while unused imports and edits elsewhere within a dependency file can invalidate callers. This is per-file evidence reuse, not a symbol-level incremental checker. Corrupt/missing cache content falls back to fresh analysis. Builds always freshly analyze, compare source/dependency bytes and policy, stage unchanged source privately, and publish atomically only after the entire current gate passes. This remains a local source artifact, without distribution/installed-consumer certification or runtime guards.

## Downstream M3 interface

`SourceGraph` owns prepared `FunctionalAnalyzer` instances, the canonical `types` registry, source/function identity maps, and replacement context. `TypeSpec(name, arguments, result, variadic)` is the recursive exact schema; canonical serialization is `str(schema)`. `Value(types, literal, items, callable)` represents established alternatives, optional literal evidence, recursively exact tuple members, and distinct callable evidence. `UNKNOWN` supplies no contract. `Binding` records first binding sites and definite initialization.

`CallableValue(parameters, returns, targets, captures, conditional)` separates concrete analyzed invocation targets from conditional input evidence. `FunctionInfo` exposes the actual node/signature/kinds/default values, captures/uses, return value, direct calls, invocation/definition failures, source dependencies, and final report contract. `FunctionalAnalyzer.matches(value, expected)` checks recursive exact data and actual callable shape; consumers must use this admission check rather than compare a familiar spelling or merely inspect `Value.kind`. `annotation_value` creates a required conditional input schema, not independent evidence about a supplied callback. `_expr` resolves concrete source values and targets while enforcing the current vocabulary.

These are internal compiler interfaces; M3 may evolve them while preserving the finite public evidence and inherited rules. Collection operations must characterize exact input/result schemas, recursive stability, callback evidence/shape, ordering, and failure propagation before extending `_expr`. No collection, record, generic protocol, ownership, or effect stub was added in anticipation of that work.
