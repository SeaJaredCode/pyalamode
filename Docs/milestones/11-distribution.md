## 3. Supported package model and producer policy

Add a closed optional table to tool policy:

```toml
[tool.pyalamode]
schema = 1

[tool.pyalamode.distribution]
schema = 1
name = "checked-pricing"
version = "1.0.0"
packages = ["checked_pricing"]
exports = ["checked_pricing.core:quote", "checked_pricing.core:Customer"]
```

Fields are exactly `schema`, `name`, `version`, `packages`, `exports`. Name is lowercase ASCII `[a-z][a-z0-9]*(?:-[a-z0-9]+)*`, at most 64 characters. Version is exactly three canonical decimal components (`0` or a nonzero digit followed by at most five digits), with no prerelease/local/dynamic version. Distribution/wheel normalization changes name hyphens to underscores only. Package names are unique public Python identifiers, at most 64 characters, and cannot collide with `pyalamode` or the characterized interpreter/stdlib/native foundation namespaces. Exports are unique public exact `module:top_level_name` selections within owned package namespaces; they select actual checked function, record or variant declarations. Nested functions and alias-only declarations are not producer export selections. A stable reexport can still resolve to the published actual declaration when consumed; its actual parent initialization remains visible.

Packages use the flat layout `root/<top-level-package>/__init__.py`, with initialized subpackages and `.py` modules. Every subdirectory containing importable Python source must have a regular `__init__.py`. Source symlinks, namespace packages, `src/` layouts, top-level module distributions, native extensions, sourceless modules, package data, entry points, scripts, arbitrary dependency metadata and dynamic build configuration are outside this first layout. They refuse rather than disappear from a claim. Exclude only the existing reserved project exclusions and ordinary `__pycache__` caches; an unrecognized package file/directory refuses the finite source-wheel layout. Package ownership is exhaustive, case-sensitive and duplicate-free. A `.py` package/module collision or casefold collision within a published namespace refuses wheel production even though compatible tree analysis retains its existing precedence rules.

All producer-root source is discovered and analyzed for writers. `build --wheel` requires the full root selection; partial positional selections refuse 2. Every exported declaration must have current strict evidence; audit/off/unverified declarations do not publish. All local source needed by owned package import/call/type/default/capture initialization must be shipped within the declared packages, or belong to explicitly declared checked installed dependencies. A sibling producer file cannot become an invisible runtime dependency. Unshipped ordinary source is recorded as producer analysis provenance only and receives no installed claim.

The existing `[project]` and `[build-system]` tables, if present, are read only as bytes included in producer policy provenance. This workflow never invokes their backends, setup.py, metadata hooks, dynamic fields or entry-point code. The distribution table above is the sole finite wheel metadata authority. Build metadata is fixed by product code.

## 5. Passive installed resolution and ownership

Use only directories observed in `[project-root, *sys.path]`, deduplicated by physical path. Non-string paths, existing archive/custom importer paths and unresolved relevant path entries refuse; do not call path hooks, finders, `find_spec`, `importlib.metadata`, resource loaders, import parents or any dependency code. Inspect the current product directory too, preserving one physical product implementation and inherited foundation/native shadow gates. Product startup itself retains ordinary Python startup assumptions; isolated `-I` commands may be used by outside controls but no consumer source imports to discover metadata.

For each declared dependency inspect immediate conventional `.dist-info` directories under observed import directories. Parse bounded static `METADATA` Name/Version, `WHEEL` and `RECORD` as data, and the product-owned evidence files below. Exactly one matching Name/version/dist-info owner is allowed. Relevant duplicate versions, duplicate physical owners, package namespace contributors, local package/module/extension/sourceless shadows or replacement candidates anywhere in the inspected path inventory refuse, even if CPython precedence could choose one. Repeated paths to the same physical owner are deduplicated. Every declared top-level package must resolve uniquely to the directory adjacent to its owning dist-info. Every parent initializer and submodule resolves within that same owner; package source cannot escape by symlink. Cross-distribution namespace merging is unsupported.

`RECORD` is parsed with a fixed CSV reader, not executed. Paths are POSIX relative paths without absolute/empty/dot/parent/backslash/NUL forms. Wheel records have exact sha256 URL-safe unpadded digests and exact sizes for all members, except RECORD itself. Installed RECORD permits the standard installer-added `INSTALLER`, `REQUESTED`, `direct_url.json`, its own empty digest/size, and supported source-cache rows; those are explicitly distinguished from wheel claims. `direct_url.json` is informational bounded data, never a resolver or approval. Unknown importable artifacts, native/sourceless files, unrecorded owned source, record duplicate paths, distribution replacement, record escape and shared top-level ownership refuse. Metadata, evidence, policy, authored copies, artifact source, actual owned package inventory, path resolution inventory and relevant caches are independently hashed; RECORD is never trusted as its own byte verification.

Runtime bytecode requires a bounded conservative check. Enumerate only ordinary CPython 3.13 cache variants for each actual importable source: `<stem>.cpython-313.pyc`, `.opt-1.pyc`, `.opt-2.pyc` under its exact `__pycache__`. Refuse source-less `.pyc`, extension precedence and unknown relevant variants. Absent caches are supported. Existing caches must have the current four-byte magic, a valid 16-byte CPython timestamp/size or checked/unchecked source-hash header compatible with the current source, and a raw payload exactly equal to either of two compiler-generated constructions for the named optimization: first, `marshal.dumps(compile(actual_bytes, actual_installed_absolute_path, 'exec', dont_inherit=True, optimize=N))`; if unequal, a helper-local `code = compile(actual_bytes, actual_installed_absolute_path, 'exec', dont_inherit=True, optimize=N)` followed by `marshal.dumps(code)`. The helper releases `code` before returning bytes; no compiled code object is retained across candidates or cache entries. Present caches therefore require one compiler/marshal construction for a temporary-form match and at most two for the retained fallback. No arbitrary cache payload is unmarshalled, normalized or evaluated. Compilation is compiler-only source validation, never execution. Bound file size and compiler errors. Equality is intentionally conservative; a legitimate cache whose payload differs from both current compiler constructions must be removed/recreated outside the checker or installed with `--no-compile`, then rechecked. This finite comparison makes no universal `py_compile` compatibility claim. Cache presence/absence and validated bytes enter the current installed snapshot and late freshness checks. Analysis-cache loss leaves all claims unchanged; executable bytecode caches are runtime resolution inputs rather than disposable analysis evidence. Ordinary post-check imports may generate equivalent caches; unchecked source/cache/importer replacement after the gate violates the runtime precondition and has no promised detection.

## 7. Producer→wheel→install→consumer evidence schema

A wheel has ordinary package `.py` files and one `<normalized_name>-<version>.dist-info/` with fixed `METADATA`, `WHEEL`, `RECORD`, and `pyalamode/evidence.json`, `pyalamode/policy.toml`, `pyalamode/sources/<package-path>.py`. Original authored bytes are always retained for explicit provenance and debug-source reanalysis. No executable metadata, backend hooks, pth files, certificate loader or runtime evidence API is emitted.

Fixed metadata: Metadata-Version 2.1, exact Name/Version, Requires-Python `==3.13.1`, Requires-Dist `pyalamode==0.1.0` and exact declared checked dependency names/versions. WHEEL is version 1.0, Root-Is-Purelib true, Generator current checker, Tag py3-none-any. Dependency order is deterministic. Existing product packaging remains ordinary; this finite builder does not replace setuptools for building the product itself in outside verification copies.

`evidence.json` is a canonical JSON envelope `{schema:1,kind:"pyalamode-checked-distribution",payload:{...},sha256:<canonical-payload-hash>}`. Payload keys are exactly:

- `identity`: `{name,version,packages,wheel_tag}`.
- `target`: `{python,implementation,gil,platforms,filesystem_encoding,filesystem_errors}`; python 3.13.1, CPython, standard, the two named platform/architecture pairs, UTF-8/surrogateescape. Observed producer UTF-8 mode is recorded separately.
- `producer`: `{checker,edition,operation_contract,standard_version,integration_version,encoding_version,product_artifacts,runtime_environment}`. Product keys must equal the current recognized 22-artifact inventory, with actual lowercase SHA256 values. Compatibility requires exact current checker/operation/encoding/product rules, not a version string guess.
- `inputs`: `{policy_sha256,sources,checked_dependencies,integration_inputs,resolution,selection}`. `sources` is producer-relative path→exact `{sha256,module,ownership,shipped,participating}` rows; `ownership` is project, `module` is the canonical shipped module or null, and `shipped`/`participating` are exact booleans. `selection` records exact per-module mode bools determined by source markers and original required-module policy. Full producer source/writer inventory is provenance; relevant shipped dependency bytes are carried and verified. `checked_dependencies` carries exact producer observed dependency snapshots, not receiver approval. Integration inputs preserve their producer-native identity and approval provenance; they cannot authorize the receiver.
- `modules`: a unique deterministic list of `{module,authored_path,source_sha256,installed_path,artifact_sha256,initialization,setup_observations}`. Paths are owned wheel-relative paths, never paths used to read the producer filesystem. `initialization` is `{source_evidence,effects,failures}`: current checked pure initialization has `effects:[]` and its finite failures; ordinary/unchecked initialization has unknown effects/failures represented by null, with separate finite recognized setup rows. Module setup never implies a certified bound for arbitrary ordinary code.
- `exports`: unique deterministic rows `{selector,kind,declaration,contract,source_location,guard}`. `kind` is function/record/variant. Declaration is the canonical actual selector. Function `contract` is the complete existing FunctionContract data; record/variant `contract` is the existing complete checked report row. Every nested field is closed and validated against the known producer schema, finite type vocabulary and owned canonical identity map; free-form claims cannot invent schemas or behavior. Source location is `{path,line,column,column_encoding}` with producer-relative authored path, 1-based positions and UTF-8-byte columns. Original producer root may be retained only as labeled informational provenance, never a consumer read authority.
- `guards`: `{mode,exports,debug,generated_files}`. Coverage is exact authored selection plus actual generated namespace/path/hash/schema coverage. Off is empty; exports are distinct original and facade selectors; debug is supported data assertions only. Callback/capability/effect/ownership/runtime-tamper coverage remains excluded.
- `artifacts`: wheel-relative path→`{sha256,size,role}` for authored runtime source, generated facade/debug source, authored copies, policy and fixed metadata. Self-referential evidence and RECORD are excluded from their own content hashes and are separately in the wheel RECORD. Roles are a closed enumeration.
- `claim_scope`: fixed product text explicitly limiting claims to listed exports, checked transitive source and separately labeled initialization/guards; unchecked shells and runtime precondition violations remain outside scope.

JSON duplicate keys, floats, NaN/Infinity, invalid UTF-8, unexpected fields, malformed digests, unknown versions/inventories, inconsistent list/map identities, path traversal, contradictory coverage, unavailable declarations and unsupported deep schemas refuse. Checksums detect accidental changes; they are not an authentication/signing service. Fresh consumer source analysis and byte derivation are the admission evidence even if someone recalculates a forged envelope checksum.

Finite limits: 64 checked distributions, 64 top-level packages per distribution, 4096 exports, 16384 source/artifact rows, 1 MiB per source/metadata-policy file, 16 MiB evidence JSON, 64 MiB total wheel/source bytes, depth 64, 500000 JSON nodes, 16384 characters per free text, 1 MiB per relevant pyc. Lists/rows are exact-type validated and bounded before expansive traversal; IO/parse/compile failures refuse. The encoding helper's tighter wire limits are independent.

During installation wheel hashes transform into an installed snapshot with exact metadata owner paths, actual source/authored/guard/cache hashes and resolution inventory, current interpreter/product/native identities, current consumer policy/approvals, and a canonical current dependency fingerprint. Paths are current provenance and source ownership, not live runtime certificates. Missing or well-formed stale/incompatible evidence refuses PAL370 by default; malformed corruption refuses PAL001/status 2; M11 has no fallback that silently imports or approves. A producer rebuild and reinstall restores the candidate, then the consumer checks again.
