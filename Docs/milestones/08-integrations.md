## Closed catalog and ordinary execution

The catalog is `pyalamode.integrations-v1`, on actual CPython 3.13.1 standard GIL builds on macOS and Linux with native filesystem UTF-8/surrogateescape. A separate `pyalamode.integrations` module contains ordinary adapters; `pyalamode.__init__` does not eagerly import that module or either external backend. The backends are the actual installed CPython standard-library native `binascii` and `_sha2` modules, not mocked dependency names. These are two bounded integrations with three operation entries. No general hashlib backend selection, OpenSSL, dynamic codecs, restoration, network transport, foreign object, mutable view, iterator, or arbitrary dependency API is admitted.

All signatures are positional-only, with exactly one exact `bytes` argument and exact `bytes` result. Ordinary invalid representations, including subclasses and memoryview/bytearray, raise `TypeError` before their hooks run. All completing operations are eager. They accept no callback, capability or dynamic option. Resource exhaustion/interruption retain the inherited exclusions.

Analyzed direct/aliased/class-dictionary writes to that complete behavioral closure fail closed. Native linked platform libraries are separately disclosed setup/foundation assumptions. ## Import/setup is separate

The adapter module imports native backends and defines fixed helpers/size bounds/functions. Native module loading reads installed artifacts and creates native types/exception objects; it is ordinary setup with IO, possible ImportError/OSError and resource-failure assumptions. This setup is never relabeled pure because later operation invocation is pure. Ordinary modules may import these adapters and select functions with `@fun`; reports publish the adapter-import setup and explicitly retain unchecked surrounding application initialization. Functional-module imports of `pyalamode.integrations`, and invocation from functional initialization/defaults/decorators/class bodies, are refused in this milestone. An ordinary shell initializes the dependency before the checked invocation.

Direct native/backend/private helper calls remain uncharacterized application operations. Approval applies to the actual resolved product adapter, including an unchanged import alias or namespace member, not to any function sharing its name. Checked wrappers and callers retain opaque external evidence; they do not convert native implementation into checked source.

## Candidate manifests, overrides and explicit approval

Product-shipped operation entries are candidates and are denied by default. `external_trust` is either `deny` (default) or `approved`; the latter admits only exact current approvals. The versioned policy adds `integration_manifests` (unique project-relative JSON paths) and `integration_approvals` (TOML arrays of exact operation tables). No command silently writes approval or makes a draft reviewed.

An optional project-local JSON override has exactly these fields: `schema:1`, `operation` (one catalog adapter identity), `status` (`draft` or `reviewed`), `base_contract_sha256`, `effects` (unique finite inherited families), `failures` (unique characterized builtin categories), `owner`, `rationale`, `provenance`. Owner/rationale/provenance are nonempty text. Paths cannot traverse outside the project; duplicate operation declarations, unknown fields/signatures/operations or malformed files are tooling errors. An override selects the same exact implementation/input/output/alias/setup contract, identifies the product candidate it extends, and may only conservatively add known effects/failures. It cannot remove baseline behavior, introduce unknown effects, change an actual checked source function or replace checked effects with unsupported purity. Source provenance and manifest path/actual bytes are reported. Draft overrides cannot satisfy strict admission even if an approval names their digest.

Each `[[tool.pyalamode.integration_approvals]]` table has exactly `operation`, `contract_sha256`, `dependency_sha256`, `owner`, `rationale`, `provenance`, and optional `expires_at`. Scope is the one exact adapter operation. Both digests are lowercase SHA-256. The effective detached operation contract includes its candidate/override provenance and actual manifest bytes; the dependency digest covers the complete detached installed identity above. `expires_at`, when present, is an explicit UTC `YYYY-MM-DDTHH:MM:SSZ` timestamp, with admission allowed only strictly before expiry. Omitting expiry is a visible nonexpiring approval, not an implied default lifetime.

Malformed/incomplete/duplicate approvals are tooling status 2. Missing, denied, draft, expired or digest-mismatched relevant approvals produce a strict policy refusal (status 1, `PAL350`). Audit reports them without a strict certificate. Unused approvals remain visible with current/stale/expired classification; they certify no operation. An expired relevant approval cannot reuse a former body hit: the current approval state, effective contract and installed identity are fresh cache inputs on every check. Build re-discovers identities/manifest bytes and rechecks expiry before publication, so a crossing expiry or identity/policy edit publishes no artifact. Relevant source/import-resolution/writer/product/runtime changes retain inherited freshness checks. Cold, full warm and partial warm serialize the same external assumptions.

The public report publishes detached candidate contracts, effective overrides, approvals and current installed identities with their digest/status, separately from each checked function's external assumptions. Function trust includes the complete relevant operation/contract/approval/dependency record, including latent returned/captured/conditional/compose/partial callable values and eager map/filter/fold/scan/group/traverse callbacks. Invocation effects/failures propagate through the existing finite call graph. Handlers discharge only characterized failure categories at that occurrence and never erase performed effects or trust. Conservative override effects must fit source and project effect bounds.

The static fixture/inspection API is `integration_contracts.operation_contract(name)` for a detached product candidate and `integration_contracts.integration_snapshot(policy=None,root=Path.cwd(),now=None)` for detached effective `catalog`, approval-status `approvals`, stable freshness `inputs` keyed by canonical dot operation identity, and tooling `errors`.
