## 3. Complete finite grammar and admission split

The parsing grammar is exactly the CPython3.13.1 Python grammar accepted by `ast.parse(..., feature_version=(3,13))`, with only the following extra statement production and changed runtime collection-display meanings. There is no general extensible grammar. Parse success is separate from strict semantic admission; all inherited unsupported Python constructs remain refused by the same checker. This references the actual stock parser used by the prerequisite rather than inventing a broader admitted language.

```text
val_stmt        := INDENT_PREFIX "val" HSPACE+ NAME
                   [HSPACE* ":" HSPACE* annotation]
                   HSPACE* "=" HSPACE* expression NEWLINE
vector_display  := "[" [expression ("," expression)* [","]] "]"
map_display     := "{" [expression ":" expression
                   ("," expression ":" expression)* [","]] "}"
set_display     := "{" expression ("," expression)* [","] "}"
annotation      := existing statically admitted Python annotation syntax
expression      := existing Python expression syntax with these displays;
                   strict admission uses the inherited finite contracts
```

`NAME` follows the stock Python identifier rules and excludes Python keywords, `val` and the reserved generated prefix below. `HSPACE` is an ASCII space or tab between tokens, never a newline. Indentation, parenthesized expression continuation and comments follow the stock tokenizer. A `val` statement starts a physical statement line after its indentation; its expression may span multiple physical lines inside ordinary delimiters. A trailing comment is allowed. One-line compound suites, semicolon-chained `val` statements and explicit backslash continuation of the declaration header are refused. Existing ordinary Python assignments remain parseable and retain the same once-binding rules.

`val` declares one simple local or module name with an initializer. Annotated and unannotated forms are supported. Destructuring, chained targets, attributes, subscriptions, augmented assignment, declaration without initializer, parameter/loop/match/except bindings and class-field `val` declarations are outside the production. Existing record/case field declarations retain their Python annotation/default spelling. A second reachable initialization still fails PAL101, including a later ordinary `=`; exclusive continuing branches and earlier returns retain PAL102/path analysis. `val` creates no block scope, runtime wrapper, cell monitor, const object or stronger ordinary-caller guarantee.

Outside strings/comments, `val` is reserved throughout `.pya`: authored identifiers/import aliases/attributes named `val` are refused except the declaration token. This prevents ambiguous future parsing. `.py` names are unaffected. The translator uses tokens and parsed syntax, never a text-wide regular-expression replacement.

Collection displays are rewritten only in runtime value-expression positions. This includes initializers, defaults, nested values, returns, call arguments, conditional branches and valid value expressions in declaration arguments. Python subscription/type-argument brackets, the annotation-only list in `Callable[[T],R]`/`Effectful`, assignment targets and match-pattern syntax are preserved. Strings, bytes, comments and string contents are never rewritten. Unsupported expression categories, including f-strings if the inherited checker refuses them, gain no admission from translation.

Comprehensions, generator displays, starred display elements and dictionary `**` unpacking are explicitly outside the immutable-display grammar. They receive a finite semantic refusal rather than a transformation into an iterator protocol. `{}` means an empty Map; there is no empty Set punctuation or OrderedMap punctuation. Use existing `Set[T].of()` and `OrderedMap.of(...)` for those cases. Tuples retain ordinary exact immutable tuple semantics. No additional constructor, protocol, operator or iteration rule is admitted.

An empty `[]` or `{}` is admitted only as the direct initializer of a simple annotated binding with the matching existing exact `Vector[T]` or `Map[K,V]` schema. Lower that case to the corresponding typed empty `.of()`. Empty displays in returns, conditional branches, nested displays or unannotated bindings are refused with an authored type-feedback diagnostic; explicit typed constructors remain available there. Nonempty displays infer exactly what the corresponding existing `.of` constructor infers; they do not add coercion, unions, callback payloads or inferred scalar-key domains. This is a finite context rule, not general expected-type inference.

## 4. Lowering, name safety and exact collection behavior

Lower `val x = e` to `x = L(e)` and `val x: A = e` to `x: A = L(e)`. Preserve the actual authored target/annotation tokens. `L` is recursively applied only at the runtime value positions listed above:

| Authored form | Generated ordinary Python form |
| --- | --- |
| `[e1, e2]` | `_pyalamode_syntax_Vector.of(L(e1), L(e2))` |
| `{k1: v1, k2: v2}` | `_pyalamode_syntax_Map.of((L(k1), L(v1)), (L(k2), L(v2)))` |
| `{e1, e2}` | `_pyalamode_syntax_Set.of(L(e1), L(e2))` |
| `val xs: Vector[int] = []` | `xs: Vector[int] = _pyalamode_syntax_Vector[int].of()` |
| `val kv: Map[str,int] = {}` | `kv: Map[str,int] = _pyalamode_syntax_Map[str,int].of()` |

Insert only the used exact product imports, in fixed Vector/Map/Set order, after the module docstring and consecutive permitted future imports, while preserving valid module-directive placement. The exact emitted alias names above and every authored identifier starting `_pyalamode_syntax_` are reserved in `.pya`. Reject collision attempts across NAME tokens, arguments, imports, declarations, match/handler captures and global/nonlocal declarations before lowering. Guard-generated names retain their existing independent exhaustive collision check. No source-selected alias or value named `Vector`, `Map`, `Set` can redirect literal lowering.

The generated aliases enter the actual checker/source graph and inherited writer/foundation scans as ordinary resolved product imports. An analyzed replacement of the product constructor/class/backend/native assumption still invalidates callers; a prefix rule is not a substitute for resolved operation identity. Imports are compiler machinery with disclosed product trust, not external approval or a new effect. Prevent source/output `.py`/`.pya` pair collisions, casefold collisions and package/module collisions before choosing any module. Never let discovery order choose the runtime owner.

| Property | Exact selected behavior |
| --- | --- |
| Evaluation | Evaluate Vector/Set items left to right. Evaluate Map pairs in authored order, key then value within each pair. Each child is evaluated exactly once. Do not sort expressions, pre-deduplicate them, thaw/freeze them or construct a transient builtin list/dict/set. |
| Early failure | A characterized child-expression failure stops before later children and before the outer constructor. Its original failure/effect/trust evidence is retained. Equal eventual unordered values do not license reordering effectful/failing expressions. |
| Vector | Uses existing `Vector.of`; retains item order, recursively validates every item in order, and preserves all earlier versions across updates. Element schema/inference is unchanged. |
| Map keys | Uses existing `Map.of`; exact homogeneous None/bool/int/str/bytes domain only. `bool` and `int` are distinct domains. Keys are validated in argument order, before value validation. No foreign equality/hash/order hook runs. |
| Map values/order | Existing canonical homogeneous scalar-key order determines stored/ordered output and validation traversal. Stable equal-key ties retain authored pair order during validation. Every supplied value is validated, including values later overwritten. |
| Map duplicates | Last supplied value wins for an exact equal key, after every key/value expression has run and all values have qualified. This is not Python dict literal behavior with an unvalidated discarded value. Map input equivalence is extensional under its existing exact-domain contract, not insertion history. |
| Set | Uses existing `Set.of`; exact homogeneous scalar members, left-to-right domain validation followed by canonical ordering/deduplication. Repeated exact equal members collapse after evaluation/validation. No general iteration or callback traversal is added. |
| Empty values | Direct matching annotated binding supplies the erased static schema; runtime empty storage is the existing constructor's empty value. An empty Map accepts its first future key only under that existing static/domain contract. |
| Validation failures | Valid recursively admitted values retain the constructors' characterized recursive failure bounds. Invalid ordinary caller data receives existing TypeError/path behavior; malformed/forged nested storage, cycles, subclasses, live capabilities, callable payloads and mutable members remain refused. No exceptions are silently converted or handled. |
| OrderedMap | Existing explicit constructor, duplicate right-wins/first-slot retention, traversal and ordered equivalence remain available; M14 supplies no alternate literal order rule for it. |

The tuple-backed O(n) copy/sort/validation costs and O(kn) retained-version limits remain the existing runtime contract. Translation changes spelling, not this backend. Homogeneous canonical sorting uses existing scalar ordering, including code-point string order and lexicographic bytes order; None has one value. Huge admitted integer diagnostics retain the existing bounded path formatter. General unordered callback/error-selection guarantees are not inferred from literal syntax.
