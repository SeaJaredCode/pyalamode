## Exact operations and failures

Every new public function is positional-only. Ordinary invalid representations raise TypeError without inspecting foreign getters, iterators, operators, repr/str or annotations. Valid arguments use exact inherited data schemas; bool and int remain distinct. Deep-data validation may reach RecursionError. Resource exhaustion and interruption retain the inherited scope limits.

| Function | Exact signature and behavior | Valid-input failure and retention |
| --- | --- | --- |
| `text_split` | `(text:str, separator:str, /)->Vector[str]`; explicit separator, native exact-str split, empty pieces retained in input order | Empty separator raises ValueError; returned tuple-backed Vector contains exact immutable strings |
| `text_join` | `(parts:Vector[str], separator:str, /)->str`; exact string items joined in Vector order; empty gives empty text | Recursive Vector validation may reach RecursionError; no foreign iterable |
| `text_replace` | `(text:str, old:str, new:str, /)->str`; native all nonoverlapping replacements, including empty-old boundary insertion | No additional valid-input failure; immutable text |
| `text_startswith` | `(text:str, prefix:str, /)->bool`; exact scalar prefix, empty prefix true | No additional valid-input failure |
| `text_slice` | `(text:str, start:int, stop:int, /)->str`; native half-open unit-step code-point slice with negative/clamped bounds | No custom index/step protocol |
| `integer_clamp` | `(value:int, lower:int, upper:int, /)->int`; inclusive exact integer bounds | lower > upper raises ValueError; may return the original immutable integer |
| `integer_parse_decimal` | `(text:str, /)->int`; `[+-]?[0-9]{1,4096}`, ASCII only, optional sign, leading zeros allowed | Grammar/digit bound raises ValueError; manual arithmetic never calls int(text) |
| `integer_format_decimal` | `(value:int, /)->str`; canonical signed ASCII decimal, zero `0` | Magnitude >= 10**4096 raises ValueError; manual division never calls str/repr/format on the integer |
| `utf8_encode` | `(text:str, /)->bytes`; manual RFC 3629 UTF-8 from exact code points, no BOM insertion or normalization | Exact UnicodeEncodeError for surrogate code points; no codec/error-handler lookup |
| `utf8_decode` | `(data:bytes, /)->str`; manual RFC 3629 UTF-8, U+FEFF retained, shortest encodings only | Exact UnicodeDecodeError for malformed/truncated sequences; no codec/error-handler lookup |
| `hex_encode` | `(data:bytes, /)->str`; exactly two lowercase ASCII digits per byte in byte order | Native exact-bytes hexadecimal formatting; no dynamic formatter/options |
| `hex_decode` | `(text:str, /)->bytes`; exact even-length ASCII hex pairs, either case, empty allowed, whitespace refused | Invalid grammar raises ValueError before fixed native bytes.fromhex |

Decimal conversion reads no locale, float/decimal context, general formatter or mutable `sys.set_int_max_str_digits` setting. Its fixed digit alphabet and `10**4096` bound are pure product initialization. A process limit of 640 or a disabled native limit cannot change these conversions. The 4096 count excludes an optional sign; all-zero inputs may contain 4096 digits, while 4097 are refused.

The initial low-level `_codecs.utf_8_encode/decode` proposal was rejected before implementation: an isolated actual CPython 3.13.1 probe demonstrated that default, None and named strict error options all invoke a replacement registered strict error handler on invalid input. The approved manual implementation therefore uses no codec module or error registry. Encoding writes ordinary 1/2/3/4-byte sequences using ord and integer arithmetic, refuses surrogate code points, and reports the first consecutive surrogate span with fixed `surrogates not allowed` reason. Decoding admits ASCII, C2–DF, E0–EF and F0–F4 lead bytes with restricted second-byte ranges preventing overlong forms, surrogates and code points above U+10FFFF. Continuations are 80–BF. It reports the first invalid start byte, invalid continuation sequence or valid prefix truncated at the end, with exact native UnicodeDecodeError and fixed reasons. No exception formatting, restoration or replacement callback occurs. Exact error category conversion remains the inherited immutable Failure operation.

## Eager ordered callbacks and ordinary closures

| Function | Exact signature and call order | Output and aliases |
| --- | --- | --- |
| `vector_scan` | `(values:Vector[T], callback:(A,T)->A, initial:A, /)->Vector[A]`; validate exact Vector and stable initial, invoke left-to-right once per item, stop on raised failure | n+1 outputs: initial then every deeply validated accumulator; immutable references retained |
| `vector_group_by` | `(values:Vector[T], callback:T->K, /)->OrderedMap[K,Vector[T]]`; callback once per item in input order | Homogeneous exact scalar K; first-key-encounter group order and original within-group order; input payloads retained without mutation |
| `compose` | `(outer:(B)->R, inner:(A)->B, /)->(A)->R`; construction invokes neither; invocation inner once then outer once if inner completes | Plain FunctionType closure retaining exact callbacks; B/R stable data; A may be an exact supported capability parameter under static effect evidence |
| `partial_first` | `(callback:(A,B)->R, bound:A, /)->(B)->R`; bound deeply validated once at construction; invocation callback(bound, supplied) once | Plain FunctionType closure; A stable data, never capability/callback; B may be an exact capability parameter; immutable bound retained |
| `result_traverse` | `(values:Vector[T], callback:T->Result[U,E], /)->Result[Vector[U],E]`; eager input order, stop on first Err or raised failure | Exact first Err returned unchanged, later callbacks skipped; all Ok yields fresh Ok ordered Vector; empty gives Ok(empty) |

Runtime callback checking establishes exact FunctionType only. It does not read callable annotations or prove purity, signature, captures, effects or dependency freshness. Those remain actual static evidence and ordinary caller obligations. Returned wrappers have ordinary function closures, no custom callable class, attributes or registration. Their capability argument passes directly to the checked inner/callback; it is neither treated as stable data nor retained by the wrapper. Intermediate/final callback results are deeply validated stable data. Unknown/foreign callback objects are refused before call; an exact ordinary function can have effects outside its static contract if an unchecked caller violates that obligation. Wrappers cannot become data payloads or guarded callable exports.

Collections use private transient exact lists for eager construction and publish tuple storage only. Group lookup uses exact homogeneous scalar equality, never arbitrary hash/equality dispatch. Empty grouping invokes no callback and yields an empty exact OrderedMap; its key schema remains static evidence. Every produced accumulator/key/Result payload is checked before retaining it. Data returned by callbacks can include the inherited exact records/cases/collections but not raw exceptions, mutable data or capabilities. Callback effects and raised failures are preserved by static invocation edges; error E is independent immutable data. The existing Vector.fold, Clock and Environment operations retain their M3/M5 runtime implementations and costs. Rooted IO retains its public interface, effects, permissions, root/path/lease checks and cleanup; its text conversion changes as described below.

## Rooted IO conversion and cleanup

The same isolated registered-strict-handler probe exposed the inherited live IO TextIOWrapper path: malformed bytes on read and surrogate text on write could execute that mutable handler. This runtime unit implements the approved minimal coordinated `effects.py` correction before M7 admission. Live read_text opens the already checked location in `rb`, reads exact bytes and calls the new manual utf8_decode while the stream remains inside its context. Live write_text opens `wb` before calling manual utf8_encode, then writes the resulting exact bytes inside the same context. Opening before encoding preserves the existing truncation behavior when surrogate encoding fails. No bytes are written before successful complete encoding; later native write/close failures can still leave partial/truncated content. Both paths close the acquired stream on success, malformed-text failure and other body exits. Newline code points remain unchanged; no BOM is inserted/removed.

Recorded IO remains exact stored text and the same declared IO effect; provider setup, rooted path permission/lstat/symlink/TOCTOU preconditions, logical borrowing and cleanup are unchanged. The IO known failure upper bound remains OSError/UnicodeError/ValueError/RuntimeError/KeyError. Native binary open/read/write/close now replaces TextIOWrapper codec behavior. Complete file bytes and converted text coexist during read; complete encoded bytes are prepared before write. Manual conversion adds O(n) transient integer/character references and final bytes/text storage; whole-file operations remain eager. The new effects import reads only the fixed standard module; standard itself imports collections/variants and has no effects import, avoiding a runtime cycle.

The follow-up OS-name contract is deliberately finite: every root, resolved root, relative path and environment name must contain Unicode scalar values, with all D800–DFFF surrogate points refused by ValueError before native OS name conversion. This includes DC80–DCFF, even though native UTF-8 surrogateescape handles those points without a registry callback. The same path/name grammar applies to recorded providers. Existing empty/NUL/dot-component/backslash/equals restrictions remain. Exact text payloads/defaults remain a separate data contract; a missing environment name can return a caller-provided surrogate-containing default without encoding it.

The supported interpreter additionally uses filesystem encoding `utf-8` and encoding error mode `surrogateescape`. Main check/build tooling rejects unsupported startup configurations with status 2 and records filesystem encoding/error mode and UTF-8 mode in runtime provenance/fingerprints. Ordinary live_io/live_environment factories read sys.getfilesystemencoding/getfilesystemencodeerrors and refuse unsupported setup with RuntimeError before native filesystem/environment access. Resolved live roots are validated after realpath so escaped raw-byte names cannot enter an admitted root. The relevant sys functions and helper code remain unchanged dependency assumptions, not a per-call monitor. Ordinary live_environment setup checks interpreter encoding and allocates a provider; it samples no environment value.

The reason for these conditions is an actual isolated CPython 3.13.1 counterexample: a replaced registered surrogateescape handler runs on D800 OS input names and can select a different file/environment name; ASCII filesystem startup can also dispatch that handler on scalar non-ASCII text. Under the supported UTF-8 condition, valid scalar names encode without an error path. Existing os.environ.get output semantics remain: arbitrary native environment bytes may produce surrogateescaped exact text. Root's actual invalid-byte/encoded-surrogate/full-high-byte probes observed the native UTF-8 surrogateescape decoder handling those bytes directly with zero registered callbacks. The runtime does not replace that backend or claim all environment values are strict UTF-8 data.

## Actual initialization and foundations

`standard.py` imports the existing collections/variants modules, defines ordinary functions, fixed ASCII digit/hex alphabets and the exact decimal bound. It performs no application call, codec/error registration, filesystem/environment/time/entropy access, provider setup or input parsing. Class/catalog initialization in inherited modules remains the separately documented product setup. Ordinary application import initialization is separate from pure export invocation. Existing live_io performs rooted filesystem setup; live_clock/live_environment construct providers without sampling their families; recorded providers validate explicit storage. Those existing setup effects/failures do not disappear because the standard catalog describes later invocation.

Direct resolved native global reads in `standard.py`: type, int, str, bytes, len, ord, chr, enumerate, range, tuple, object, ValueError, UnicodeEncodeError and UnicodeDecodeError. Exact-str split/join/replace/startswith/subscription, exact-bytes hex/fromhex/subscription, integer arithmetic/comparison/bit shifts/and/or and `//`/`%`, and native tuple/list literals, construction, iteration, append and reverse are additional implicit native foundations. TypeError and types.FunctionType are read transitively by collection validation. No `_codecs`, codecs.lookup/register/register_error, sys integer conversion setting, external trust, hash/randomized traversal or general format operation is read by the new pure functions. Exact Unicode exception constructors receive only internally controlled scalar indices/reasons and exact input text/bytes. Product dependencies are fixed standard function/helper code and `_exact`, `_vector`, `_DIGITS`, `_HEX_DIGITS`, `_DECIMAL_DIGITS`, `_DECIMAL_LIMIT`, collections Vector/OrderedMap, `_invalid`, `_validate`, `_storage`, `_validate_key`, `_function`, `_new`, and variants Ok/Err construction and fixed slot payload access through object.__getattribute__, plus their complete inherited transitive collection/record/variant/native foundations. Rooted IO additionally retains its full M5 path/OS/provider/lease foundations and reads standard.utf8_encode/decode plus builtin open and native `_io.BufferedReader`/`_io.BufferedWriter` context/read/write/close and their native file foundations. It removes TextIOWrapper codec/error-registry dispatch from file contents. Effects adds `_scalar_text` (ord/surrogate checks) and `_filesystem_runtime` (sys.getfilesystemencoding/getfilesystemencodeerrors and RuntimeError), while main runtime provenance also reads sys.flags.utf8_mode. Native OS name/environment output conversion remains the characterized supported UTF-8/surrogateescape path described above. Static metadata must characterize these actual identities and reject relevant alias/helper/native dependency writers.

No additional backend or license dependency is introduced. The new code is original product code; native CPython and inherited standard-library foundations retain their existing licenses. Unchecked behavioral rebinding remains a conditional execution assumption, rather than a protected process or live dependency identity monitor.

## Costs, evidence and approval boundary

Text work/storage is proportional to native input/output length under the finite operations; joins additionally visit n Vector elements and their deep validation. Manual decimal parsing/formatting has a conservative O(d²) big-integer arithmetic bound with d <=4096; output stores O(d) characters. Manual UTF-8 scans n code points/bytes and stores O(n) output before final immutable materialization. Grouping uses O(ng) exact scalar comparisons for n items/g groups, O(n+g) temporary/result references and native scalar comparison costs, plus callbacks/deep validation. Scan stores n+1 accumulator references and validates every result; traverse stores visited successful values until first Err or completion. Composed invocation has two callbacks and intermediate/result validation; partial construction validates its bound and invocation has one callback/result validation. Deep nested data retains inherited recursion/catalog-scan costs; retaining earlier versions/results retains their payload graphs. No constant-time or general speedup claim is made.

Meaningful runtime gates will cover all twelve scalar operations, 4096-digit boundaries under changed native limits, exact bool/int/subclass/foreign refusals without hooks, arbitrary Unicode including NUL/BOM/non-BMP/surrogates and malformed byte boundaries, registered strict replacement handler with zero calls, scan/grouping order and immutability, empty inputs, stable bound retention, raised-callback short circuit, first Err identity/skip semantics and capability pass-through without retention. Native and Docker Linux use actual CPython 3.13.1 standard GIL builds with networking disabled. Main/reviewer/root retain static graph/cache/nonexecution and actual artifact gates.

The benchmark protocol was separately approved by root before intervals: six named pure-data workloads (text/decimal pipeline, UTF-8/hex round trip, scan, grouping, composed/partial calculation, Result traversal) at n=10/100 through actual checked off/exports/debug artifacts, with three trials of 25 calls and ten warmups per row. Actual sequential native and Docker Linux runs on the corrected approved freeze each completed 36 rows, 108 intervals, 2,700 measured calls and 360 warmups. Every correctness assertion and separate untimed IO/Clock/Environment/setup smoke passed. Build/import/input preparation/guard counting/warmups/correctness/hashing/JSON writing are excluded; loops, native/library/generated assertion work, transient disposal and tracemalloc are included. Only the last interval result is retained, memory is Python-traced allocation rather than RSS, OS caches/load are uncontrolled. No product/test/harness source changed after freeze.
