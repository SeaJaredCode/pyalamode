## Exact approved adapter catalog

All public signatures are positional-only, with exactly one exact `bytes` argument and an exact `bytes` result. No keywords, optional algorithms, alternate alphabet, newline mode, buffer protocols, strings, subclasses, callbacks, capabilities or arbitrary options are admitted. Type validation precedes length or backend calls; a foreign object, memoryview, bytearray or bytes subclass raises exact TypeError without running its getters, iterators, buffer hooks, operators, formatting, truth testing or restoration. Exact immutable bytes need no copy to establish their stability. Resource exhaustion, process interruption and hostile interpreter modification retain inherited exclusions.

## Ordinary setup is separate from invocation

The new module imports `binascii as _binascii` and `_sha2 as _sha2`, defines the adapter functions and fixed integer bounds, and performs no adapter call at import. It is deliberately absent from eager `pyalamode.__init__` imports. Ordinary application import of this module performs backend import/native-loader setup before invocation; it remains ordinary initialization, with external setup provenance and a known IO loading branch. The initialization record must not certify arbitrary surrounding imports or user initialization merely because a later operation is approved pure. Strict functional modules cannot import this ordinary setup under a pure initializer claim. An ordinary shell/module may import the adapters, then expose individually checked calculation functions under explicit project approvals.

Extension initialization creates native types, functions and exceptions in private module state. Native library loading and process importer behavior have independent setup assumptions and may fail with ImportError/OSError or resource failures. Cached imports may reuse modules, but that does not convert the import contract into pure setup. A changed `sys.modules` backend, importer/finder/loader, backend binding, builtin or adapter global violates the runtime dependency precondition; analyzed relevant writes must invalidate subsequent admission. No adapter performs an approval lookup, artifact comparison, module re-import or certificate check on invocation. Ordinary Python can invoke these functions without a project approval and obtains ordinary runtime behavior, not a checked claim.

The unsafe marker remains a separate main-owned ordinary Python identity declaration. Unknown adapters, even those claiming pure behavior or supplying exact/copy-validated output, remain outside certification. A shell may run an unsafe adapter and explicitly freeze or convert its output, then start a new checked computation; that computation does not certify the preceding unsafe work. Unknown adapters cannot be authorized by adding effect names or selecting these narrow approvals.
