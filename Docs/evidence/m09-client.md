## Launch and workspace contract

One local `file:` Python workspace is supported per server child; remote/virtual documents and multi-root workspaces are explicitly unsupported in this bounded first client. The client selects existing Python files within the canonical workspace and sends their canonical source URI to the server, whose workspace/symlink gate remains authoritative. It maps returned diagnostics, navigation and previews back to the actual open editor document URI, including macOS `/tmp` versus `/private/tmp` spellings. Simultaneous open editor aliases for one canonical source file explicitly fail because they cannot supply one unambiguous overlay. A user/machine setting `pyalamode.pythonPath` supplies an explicit absolute interpreter executable; absent/invalid configuration produces a visible setup error and no child spawn. The guide uses the actual supported `.venv/bin/python`. No shell, command interpolation, pip installation, application entrypoint, interpreter auto-detection hook or arbitrary launch argument is used.

Agreed server launch is `<absolute-python> -I -m pyalamode.editor --stdio --root <absolute-workspace>`, with `cwd` set to the workspace and piped stdin/stdout/stderr. Main also provides `pyalamode editor --stdio --root ...`; the extension uses the explicit interpreter form. The configured executable spelling, including literal `.venv/bin/python`, is preserved; resolving its symlink to a base interpreter could lose the installed environment and is forbidden. The server initializes from matching `rootUri`. The client validates UTF-16 and schema 1, displays checker/target/root/runtime provenance and records the literal spawn path/args. Observed initialization metadata is `capabilities.experimental.pyalamode={schema:1,target,pythonExecutable,pythonVersion:[major,minor,patch],platform,root,filesystemEncoding,filesystemErrors}` from built-in actual server metadata. A handshake incompatibility is a tooling error, never a clean editor view.

The extension declares local desktop support and no untrusted-workspace support. A restricted VS Code workspace starts no configured executable; trusted workspace status authorizes the local tool process and is distinct from Pyalamode external-operation approval. It never changes project permissions, effect bounds, approvals, expiry or ignored findings. Tests isolate all profiles/extensions/workspaces and never write to the user's normal profile or extensions directory.

Before child construction the exact host gate also requires `vscode.env.remoteName === undefined` and `vscode.env.uiKind === vscode.UIKind.Desktop`, in addition to one local root/trust. ## Transport and lifecycle

Transport is a finite LSP-compatible JSON-RPC 2.0 stdio subset. Header bytes are ASCII and messages use `Content-Length: <UTF-8 byte count>\r\n\r\n` plus UTF-8 JSON. Buffer parsing accepts fragmented headers/bodies and multiple frames in one read. It rejects malformed/duplicate lengths, unsupported content encoding, invalid UTF-8, oversized header/body, malformed JSON or response structure and unexpected IDs with a visible terminal transport failure. Bounds are an 8KiB header and 8MiB body. The client treats an invalid server frame as terminal; the server's recoverable known-length incoming request errors are returned as valid JSON-RPC errors and do not stop this client. No batch requests, TCP listener, network endpoint or process-wide registry is introduced. Stdout is protocol only; stderr is bounded ordinary tool output and cannot be mistaken for a successful check.

Numeric request IDs increase within a child lifetime. At most 128 requests are pending; each has a 30-second default deadline. Pending requests resolve once, with result/error kept distinct. All pending requests reject on spawn/stream/parser/child-exit failure. Editor cancellation rejects locally and retains at most 128 late response IDs; no server cancellation guarantee is advertised. A later response beyond that finite retained window fails closed as an unexpected ID. Unexpected server requests receive method-not-supported; supported notifications are diagnostics and tool/log state. Stderr is limited to 64KiB per owned child. Error-level server tooling notifications clear current findings and show an explicit unverified error. The client does not execute commands supplied by arbitrary server payloads.

Sequence: spawn, `initialize`, validate advertised capabilities/protocol/UTF-16 and exact runtime/root/executable provenance, send `initialized`, set initialized readiness, synchronize existing open documents, then serve editor requests. Shutdown allows two seconds for `shutdown`, sends `exit`, closes streams and allows one second before terminating only its own child. Stop/deactivate/configuration/workspace changes clear current diagnostics and dispose request timers/subscriptions. Restarts are serialized, and callbacks from former children cannot publish current findings. A visible restart command starts a new lifecycle; crashes do not retain a former successful claim or enter an unbounded automatic restart loop.

Agreed capabilities are `textDocumentSync={openClose:true,change:1,save:{includeText:false}}`, hover/definition/references/document symbols and code actions; position encoding is **UTF-16**. All document changes are full text. `didOpen` sends `{textDocument:{uri,languageId:"python",version,text}}`; `didChange` sends `{textDocument:{uri,version},contentChanges:[{text}]}` with actual increasing editor versions; `didSave` sends `{textDocument:{uri}}`; `didClose` sends `{textDocument:{uri}}` and returns the server to disk evidence. The server refuses duplicate/decreasing versions; the client never fabricates lower versions. It synchronizes open overlays before queries, discards obsolete diagnostic notifications/results and never labels outdated evidence current. Dependency/policy/artifact changes and explicit refreshes request new server analysis rather than reusing a client certificate.

## Editor behavior and shared payloads

Providers apply only to local `python` documents in the selected workspace. Zero-based end-exclusive UTF-16 ranges are passed through to actual VS Code Position/Range objects; AST UTF-8 byte conversion belongs to the shared server and is tested through actual non-ASCII/astral/CRLF documents. Diagnostics preserve engine rule code, severity, authored source/range, related first binding, affected boundary, origin, reason and remediation. The Problems view renders these findings; a tooling/server failure is visibly distinct from an empty successful diagnostic set.

The agreed `textDocument/publishDiagnostics` envelope has `uri`, open document `version` (omitted for closed files) and `diagnostics`; each row has `range`, `severity`, `code`, `source`, `message`, optional `relatedInformation`, and `data={boundary,origin,reason,remediation,authored:{path,line,column,end_line,end_column,column_encoding},snapshot,version,diagnosticIndex}`. `column_encoding` distinguishes AST UTF-8 byte and tokenize/SyntaxError code-point producers; the client consumes only already converted UTF-16 `range`. It preserves diagnostic data for explanation/preview requests. Hover uses server-provided contract content: exact input/results, enforcement/behavior, checked/opaque/unchecked source evidence, required/declared effects and paths, transitive external assumptions, failures, freshness and selected guard coverage. Unsupported/unresolved symbols receive no invented source destination or clean contract. Definition/references/document-symbol providers use actual server source identities, not text search or familiar spelling. Navigation is deliberately limited to participating declarations and actual direct checked-call occurrences supported by engine edges; shadowed/local parameter/dynamic/unknown targets return no destination.

Commands provide explicit refresh/restart, contract/explanation inspection, a safe fix preview and authored guard-boundary navigation. The exact main custom schema is:

| --- | --- | --- |
| `pyalamode/project` | `{}` or `{audit:boolean}` | `{schema:1,snapshot,freshness,inputs,report,documents:[{uri,version:null|int}],regions:[{uri,range,selectionRange,name,kind,mode,contract:null|object}],diagnostics:[{uri,...LSP diagnostic}]}`; `report` is the unchanged complete `ProjectResult.to_dict()` |

Read-only evidence text/hover escaping treats filenames, rule messages and authored source as data; raw HTML and arbitrary Markdown command links are disabled.

Agreed code actions contain command `pyalamode.preview` with one argument `{uri,version,snapshot,diagnosticIndex}`. The client sends that same closed object to `pyalamode/preview` and preserves the response above, including its limits. It validates matching URI/version/snapshot and current source text before showing a preview. It registers read-only virtual documents for before/after and invokes the built-in `vscode.diff`, retaining a source link and remaining blockers/semantic choices. It never calls `workspace.applyEdit`, saves a preview, executes a returned program, modifies policy or auto-applies a fix. A stale/missing/unsupported preview is shown as an explicit explanation. Main is responsible for finite straight-line SSA/fresh ignored-update eligibility, behavior preservation or explicit remaining semantic choice and unchanged failure behavior; the client does not broaden it.

Selected guard failures use a user-selected local artifact URI/public boundary/phase/name, then navigate through `pyalamode/guardLocation` and the server's exact generated-to-authored boundary/evidence freshness checks. The client opens only validated local authored locations and shows guard mode, argument/return/debug-local coverage and value path separately from source/effect/trust evidence. It does not parse an arbitrary exception message as certification or run/import an artifact. Off artifacts retain their ordinary caller obligations.
