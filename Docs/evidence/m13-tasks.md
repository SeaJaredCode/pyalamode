# M13 finite task contract and held cost protocol

M13 adds `Task`, `TaskCapability`, `live_tasks`, `controlled_tasks`, `task_map` and `task_map_with`. The synchronous eager operations accept an exact checked callable and exact deeply stable `Vector` messages. Successful results are a new exact `Vector` in message input order. The static checker establishes fixed signatures, schemas, captures, effects and dependencies; runtime exact function/data validation alone establishes none of those callable facts.

## Public setup and invocation

`live_tasks(workers, /, *, max_tasks=256)` is ordinary setup. Both arguments require exact integers, excluding bool/subclasses. Workers are 1..4 and maximum messages 1..256. Wrong type raises `TypeError`, numeric range raises `ValueError`. It creates an opaque idle owner-thread provider and starts no worker or external application observation.

`controlled_tasks(order, /, *, cancel_after=None)` is ordinary setup for a bounded test provider. Order is an exact tuple permutation of `range(len(order))`, with exact integer members and size0..256. The optional cutoff is None or an exact integer0..size. Wrong shape/type raises `TypeError`; duplicate/permutation/range errors raise `ValueError`. Every invocation must have exactly the configured cardinality. Order and cutoff are fixed and reusable; this is not an advancing recorded cursor or an arbitrary instruction scheduler.

`task_map(tasks, callback, messages, /)` invokes a fixed unary checked callback over stable data messages. `task_map_with(tasks, capability, callback, messages, /)` invokes a fixed callback `(capability,message)->result` with one exact IO/State/Clock/Random/Environment interface. Task is excluded as the injected external interface. `_with` runs on the owner/caller thread, with a fresh logical borrow per callback and result validation inside that borrow. Controlled providers and live workers1 are supported; live workers2..4 raise `ValueError` before callbacks. Live workers1 also executes plain `task_map` serially on the caller thread.

The six names are reexported by `pyalamode`. Task/TaskCapability are defined in effects.py; the four factories/operations are defined in tasks.py. TaskCapability offers no public method, direct constructor, subclass, stable-data schema, status query, cancel/poll/future/result/handle API or checked capture/storage/return permission. Public attribute assignment/deletion raises `AttributeError`. Borrowed Task views obey inherited enclosing lease lifetimes and cannot escape checked scopes.

## Messages, callable evidence and effect preservation

Runtime admission first checks the exact live idle Task provider, fixed private configuration, enclosing leases, owner thread and status. Closed/wrong-thread/busy/revoked use raises `RuntimeError` before supplied callback/messages. Provider is busy through admission, invocation, final validation and cleanup. Admission failures restore idle. Plain admission then checks exact FunctionType callback, exact Vector receiver, complete inherited recursive stable validation and size/schedule agreement. `_with` checks the injected exact live pre-M13 interface before callback/messages, then its live worker constraint after complete data/size validation.

Inherited exact scalar, tuple, collection, record, variant/Option/Result messages and results are admitted. Forged malformed/cyclic/foreign/mutable nested data, builders, capabilities, callables and live views are refused at inherited nested paths. No arbitrary iterator/getter/hash/equality/representation/conversion/annotation evaluation occurs under unchanged dependencies. Runtime does not inspect annotations, defaults, closures or globals, infer purity/capture stability, or maintain callable certification. An ordinary exact function with an incompatible arity raises ordinary Python `TypeError` at invocation. Ordinary mutable captures can execute without gaining any checked claim.

Checked source requires stable message/result schemas and current actual callable/dependency/capture evidence. No capability/builder/live-view/foreign mutable/changing-cell capture is admitted. Task maps retain `Task` plus the complete declared/conditional callback effect union. A declaration-only Clock callback retains Clock even when computing integer arithmetic. `_with` retains its injected family and all callback bounds. Controlled/recorded providers, cancellation and handlers do not erase effects, failures, trust or execution preconditions.

The caller must preserve the enclosing external lease and exclusively own the lent external provider for the complete synchronous operation. Existing five providers gain no synchronization, cross-thread transfer, OS exclusivity, transaction or snapshot promise. Completed State updates, IO writes and Clock/Random cursor consumption survive failure/cancellation. No rollback or partial result is published.

## Scheduling, cancellation and failure

Live workers2..4 starts fixed consecutive input-index waves of at most workers items, one fresh native joinable thread per message. Start requests are input-index ordered; callback entry/completion within each wave are unspecified. A wave is joined before another begins. Worker callback failures do not suppress sibling start requests in that wave; the first failing joined wave suppresses all later waves and rethrows the identical lowest input-index callback/result-validation exception object from that wave.

Controlled execution runs serially in the exact configured permutation. It stops at the first scheduled callback/result-validation failure and rethrows the same object. A successful configured prefix shorter than the full input raises exactly `RuntimeError("tasks: configured cancellation boundary reached")`; cutoff equal to cardinality completes, including empty0. Complete invalid message admission wins cutoff0; a prefix failure wins later cancellation. No running thread is preempted. There is no dynamic cancellation method/checkpoint/controller API.

Each callback result is recursively validated before recording success. The complete successful input-ordered result Vector is deeply validated before publication. Stable nested aliases can be reused, and prior immutable input/results persist. No task handle or live staging view escapes. Valid-operation own conservative failures are RecursionError/RuntimeError/ValueError plus callback raised-failure bounds and `_with` inherited capability/borrow failure bounds. Invalid ordinary types/storage/result representations use TypeError. Memory exhaustion, divergence, interpreter shutdown and repeated process interruption retain inherited limitations.

## Ownership and native cleanup boundary

Task private provider data is `(workers,max_tasks,order,cutoff,owner_ident)`. Index0/1/2 means idle/running/permanently revoked. The creating native thread owns the provider; one active call is allowed. Normal callback failures, BaseException, cancellation and validation failures complete all ordinary started joins before restoring idle and propagating. Every fresh external borrow closes on success, result failure, callback Exception/BaseException and cancellation boundary; dependent views close with it. Task borrow exit checks owner without requiring idle/nonrevoked status, so a body/coordinator exception is not masked by revocation.

The native backend is pinned to CPython3.13.1 standard GIL, macOS arm64/Linux aarch64 UTF8/surrogateescape. It uses `_thread._ThreadHandle`, `get_ident` and `start_joinable_thread(callback,handle=handle,daemon=False)`, without importing threading/Executor application facilities. Every attempted handle is tracked before launch. A nonzero native handle ident identifies an actual start even when the launch call raises after starting. Workers catch all callback/validation BaseException into private slots, avoiding native unraisable propagation.

The first coordinator BaseException, including Python wave-loop transitions around native launch/join, takes precedence over callback and later cleanup failures, preserving identity. Future starts stop; every attempted nonzero-ident handle receives an initial join. Failed initial joins receive at most one additional retry each, after all initial joins and in original order. Per-handle attempt counters also bound recovery after a loop-transition interruption; fallback cleanup revokes before joining and restores eligibility only when every known started handle is joined. A second interruption of cleanup retains the disclosed process boundary. Successful cleanup restores idle. An unresolved retry permanently revokes the provider and prohibits future operations. Private references are dropped; a slot still owned by a worker is not mutated if repeated native interruption prevented joining. Running threads are never killed. Repeated signals/OS join failure can prevent complete termination; this exceptional process boundary is disclosed, not reported as a joined batch.

The direct native launch emits a CPython audit event before launch. Supported execution assumes no application audit/trace/profile/monitoring hooks introducing unknown behavior. Analyzed actual `sys.addaudithook` registration invalidates the task foundation, including resolved aliases. Runtime does not inspect a hidden hook registry. Hook installation outside analyzed source/after checking, unchecked dependency/private-storage replacement, fork/shutdown and out-of-scope thread-ID reuse violate execution preconditions. No reflection sandbox or universal race detector is offered.

Primary native source is [CPython v3.13.1 _threadmodule.c](https://raw.githubusercontent.com/python/cpython/v3.13.1/Modules/_threadmodule.c), retained in the reviewed runtime plan with local pinned threading/test_thread source evidence. Native handles begin ident0, receive ident on successful start and support idempotent join; join can process pending calls and be interrupted. The private API has no general Python-version portability claim.
