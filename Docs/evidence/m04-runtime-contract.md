# M4 ordinary runtime contract

The M4 runtime consists of original product code in `pyalamode/records.py` and `pyalamode/boundaries.py`, with record hooks in the existing tuple-backed collections façade. It adds no installed package, vendored library, copied interpreter implementation, external storage backend, function-purity registry, or mandatory invocation wrapper. Stock CPython 3.13.1 supplies its ordinary tuple, slot, class, AST, dataclass and namedtuple implementations under the interpreter's existing PSF and incorporated-software notices described in the [M3 handoff](../milestones/03-collections.md). Reference method generation uses the installed standard library; this project does not redistribute that library.

## Records

`@record` accepts an exact ordinary declaration class with the direct `object` base, public identifier fields, closed exact data annotations, and deeply validated stable defaults. Required fields precede fields with defaults. It rejects custom bases/metaclasses, methods, constructors, getters/descriptors, private/reserved fields, unsupported annotations, and mutable or wrongly typed defaults. Exact module/name/qualname metadata and annotation keys are checked before namespace/hash lookup. Annotation strings are parsed through a finite AST grammar; expressions, calls, arbitrary type subscriptions and `get_type_hints`/application annotation evaluation are excluded.

The decorator returns an exact generated class with one builtin slot descriptor per field and a private initialized slot. Constructors validate every field against its recursive schema before filling slots. Field reads use ordinary builtin slot storage. Ordinary assignment, deletion, reinitialization and subclassing fail; records expose no instance dictionary and are unhashable. Generated `__match_args__` supports ordinary Python field patterns, although M4 makes no static pattern-matching admission claim. Equality distinguishes concrete record classes and recursively exact value types; product-side comparison with foreign objects returns false without calling their hooks. Repr delegates only to the existing admitted scalar/tuple/collection/record representation vocabulary and retains CPython scalar formatting limits.

`replace(record, **changes)` validates the existing record and all changed fields, rejects unknown fields, and returns a new exact concrete record. Earlier records and nested immutable values remain stable. Constructor and replacement keyword keys must be exact strings. CPython binds `**kwargs` before entering the product function, and that binding itself can call a string-subclass key's hash/equality. The runtime rejects those keys before adding any further foreign calls; tests compare the call-stage hook count with an ordinary function of the same signature. That Python call-stage behavior is outside the data validator's coverage.

Record schemas/defaults live in an immutable tuple of class metadata, recognized solely through `is` identity. Looking up an arbitrary object type never hashes or compares its foreign metaclass. This describes data classes; it is not a service establishing callable purity. Unchecked mutation of product definitions, slot descriptors, registry bindings or foundational interpreter/standard-library dependencies violates the disclosed dependency assumptions. Ordinary immutability checks are not hostile-Python isolation.

## Snapshots and independent exports

`freeze(value, *, exclusive=False, adapter=None, schema=None)` runs in an ordinary shell. Exact list becomes Vector; exact tuple becomes tuple; exact insertion-ordered dict becomes OrderedMap; exact set/frozenset becomes Set. Keys and set members retain the M3 homogeneous exact scalar domain (`None`, bool, int, str or bytes). Unsupported container-valued keys/members fail rather than introduce new hashing/equality contracts. Existing admitted product values and scalars may be validated and reused. Nested mutable sources are converted recursively; subclasses, arbitrary objects, iterators, live views, capabilities and cycles fail with a nested path. Shared acyclic references are copied by value, with no alias-identity preservation contract.

Any recursively reached mutable builtin or named adapter source requires exact `exclusive=True`. It asserts that the caller supplies exclusive access for the duration of snapshotting. The library does not infer ownership or acquire a lock. Length changes and builtin iteration instability that are observed fail explicitly; arbitrary same-size or restored-size concurrent changes cannot be universally detected. A caller violating exclusive access receives no consistent-snapshot claim. No unimplemented synchronized-adapter assertion is offered.

The optional `schema=` argument accepts the same finite exact runtime data annotation vocabulary as record declarations, then validates the completed result against it. It does not make reading mutable input pure. Unsupported schema metadata is never evaluated as an application expression. Static caller evidence, when admitted by the checker, concerns the validated resulting data; mutable source access and exclusive-access obligations remain explicit boundary assumptions.

`thaw(admitted)` first checks deep admitted data, then exports a fresh list for Vector/tuple, dict for Map/OrderedMap, set for Set, and field dict for records. Every container occurrence is independently allocated, including repeated references and repeated exports. Exact immutable scalar leaves can be reused. Mutating any nested export cannot mutate its source or another independent export. No source object's restoration, constructor, iterator or formatting hook is used.

## Finite named adapter qualification

`dataclass_adapter(Source, ExactRecord)` and `namedtuple_adapter(Source, ExactRecord)` produce immutable adapter metadata for the exact concrete source and target. Generic `freeze` does not admit dataclasses, namedtuples or a generic foreign record shortcut. Adapter input still requires `exclusive=True`, including frozen dataclasses and namedtuples, because their field payloads are not necessarily immutable.

The supported dataclass has a direct object base, exact standard metadata, positional fields in the target's order, generated init/repr/equality and match metadata, stable defaults and optional standard frozen setters/hash. Inheritance, slots, keyword-only fields, ordering, default factories, post-init/custom methods, custom constructors and descriptors fail. The qualifier compares standard generated method code, defaults/keyword defaults, relevant globals/builtins and closures with a trusted standard-library reference generated solely from exact field names, object annotation metadata and stable defaults. Code names and every namespace dictionary key are checked as exact strings before lookup/comparison, so a colliding foreign dictionary key cannot invoke its equality hook. A constant reference docstring avoids signature generation; `inspect.get_annotations` reads only the product-generated reference with `eval_str=False`. It never evaluates source annotations. Storage is read through the retained exact generated builtin `__dict__` descriptor, bypassing newly installed application properties.

The supported namedtuple is a direct tuple subclass created by the standard namedtuple generator, with the exact target field order and stable suffix defaults. Generated methods, constructor globals/defaults/closures, empty slots and match fields must qualify. Each exact builtin field getter's index and doc metadata must match the standard reference; swapped getters fail. Conversion reads physical tuple slots using builtin tuple operations, then calls the exact product target constructor. An arbitrary method or annotation never supplies compatibility evidence.

Factories qualify the definitions as they exist then. Unchecked later behavioral mutation invalidates the compatibility/dependency assumptions; conversion does not install a universal live identity monitor. The conversion itself never invokes a source constructor or source method. Field values still undergo recursive snapshotting and exact target schema validation, so compatibility metadata does not admit unsupported payloads.

## Supported guard coverage

`validate_data(value, schema, *, path='value')` consumes checker-generated ordinary schema data: exact scalar strings, fixed/homogeneous tuple descriptors, the four collection descriptors, or an exact product record class with its fixed field descriptors. It returns the same value after recursive exact validation. Schema shape is validated first; foreign class/type metadata, callable descriptors, arbitrary annotations and inconsistent record field schemas fail without application hooks. It distinguishes bool/int, rejects subclasses and erased wrong generic contents, and reports the authored argument/result/data path.

Guards are off by default. The build's selected export façade validates supported arguments before entering the original function and validates returned data after it returns. It preserves the original function object in the original module, so direct checked internal calls receive no generated wrapper or repeated boundary validation. Debug additionally inserts supported data assertions at checked parameter, local-binding and return sites. Callable boundaries are refused, since annotation-only validation cannot establish callback purity or captures. Data guards do not prove effects, ownership, stable dependencies, hidden behavior of arbitrary Python, or integrity after unchecked mutation.

The measurement harness builds the actual off/exports/debug artifacts. Its selected public entry makes eight direct calls to an unselected checked leaf, returning the same nested data. Untimed counting records zero deep assertions in off mode, two at the selected export in exports mode, and 28 in debug mode (two export plus one entry parameter, eight times leaf parameter/return/local, one entry return). Counter aliases are removed before timing. The [measurement report](m04-runtime-measurements.md) and platform JSON publish costs and source/hardware gates.

## Foundation and actual costs

The new finite foundation gate extends M3's explicit and implicit builtin reads with list/dict/frozenset/range/staticmethod, parsing/exception operations, and the standard dataclass/namedtuple reference-generator operations. It includes closed AST parsing and sys.modules namespace reads; exact type/descriptor/code identities; dataclass helper metadata and generated methods; namedtuple field getter metadata; class preparation; keyword recognition; annotation metadata reading; abstract-class updates and recursive-repr decoration. Standard generators may compile/execute their own generated reference source. They do not execute application annotations or source constructors. Concrete module/name inventory and analyzed writer routes are recorded by `RECORD_FOUNDATIONS` in the checker; those conditions do not admit application calls to those names. The full product byte digest map includes records, boundaries and guard generation.

Let f be fixed record fields, D be recursively visited data occurrences including repeated aliases, R be registered record classes, N be snapshot container/leaf occurrences, and h be nesting depth. Scalar length and diagnostic-path construction add costs.

| Work | Source bound and storage |
| --- | --- |
| Record construction | O(f + D), plus O(R) record recognition per relevant visited type; O(f) slots |
| Ordinary field access | O(1) builtin slot read |
| Record replacement | O(f + validation of old/new data); new O(f) outer slots, stable unchanged fields reused |
| Record equality/repr | O(f + recursively compared/rendered data), plus relevant record-recognition searches; recursive stack |
| Schema/deep assertion | O(schema syntax + D), with O(R) exact-record schema/recognition searches; no allocation of copied data |
| Record metadata lookup | O(R) identity-only tuple scan; declaring R classes also copies growing metadata tuples |
| Snapshot | Recursive by-value copying; constructors may revalidate already converted descendants, giving O(Nh) validation/copy work plus homogeneous key/member sorts; result proportional to copied occurrences |
| Thaw | O(D) generic validation plus independent container allocation, with O(R) relevant recognition searches; O(D) fresh mutable storage |
| Adapter qualification | Generated reference source/code, field and complete function-namespace key scans, including standard-library generation and nested defaults validation; performed when creating the adapter |
| Record declaration | Closed annotation parsing, complete module/annotation-namespace key scans, defaults validation and growing record-metadata tuple copy |
| Retained record replacements | O(kf) outer slot references for k versions; immutable unchanged field objects may be shared |

No structural-sharing tree, universal latency, ownership-detection or general speedup claim is made. Product constructors keep their ordinary invariant validation even when function guards are off. Recursion depth can produce `RecursionError`; resource exhaustion/process interruption remain outside finite supported execution guarantees.
