# M11 distribution engineering evidence and contract

This increment publishes ordinary source wheels with export contracts and checks real installed dependencies from a separate consumer project. No application module, import parent, annotation/default/decorator, metadata hook or arbitrary build backend executes during static checking/building. Ordinary runtime calls require unchanged checked dependencies and exact caller contracts; the gate provides no protection against subsequent unchecked mutation.

Current checker is `checked-distribution-11.0`; operation catalog is `scalar-tuple-call-collection-record-boundary-effect-domain-failure-standard-integration-encoding-distribution-ops-11`. The exact product inventory is 22 foundation files and 23 package `.py` files. Target is CPython 3.13.1 standard GIL, macOS arm64 or Linux aarch64, native UTF8/surrogateescape. Standard, integration and encoding catalogs remain separate. [The executable plan](../milestones/11-distribution.md) and [fixed conformance cases](../conformance/m11-cases.md) define release scope.

## Actual producer and consumer APIs

Producer policy has exact `[tool.pyalamode.distribution]` keys `{schema,name,version,packages,exports}`. Schema is 1, name is bounded lowercase hyphenated ASCII, version is three canonical decimal parts, packages are initialized public flat-layout top-level packages, and exports are exact actual public top-level function/record/variant selectors. All producer source is scanned for writers; required local source must ship. The builder does not invoke `[project]` or `[build-system]` hooks. Wheel metadata is fixed by product code.

Consumer `[[tool.pyalamode.checked_dependencies]]` rows have exactly `{schema,name,version,packages}`. A declaration selects passive discovery and fresh static analysis. The consumer independently supplies its current trust approvals, effect bounds and explicit-case policy. Producer approvals are provenance. Installed canonical module names and actual source identities join the existing source graph, writer closure, call/callback inference, failures, effects, trust and initialization gates. Consumer `require_modules` applies to owned project source; installed selection comes from original declarations and required-module evidence.

`pyalamode build --wheel --root PRODUCER --output FRESH/CANONICAL_NAME.whl --json` calls `build_paths(..., artifact="wheel")`. Default artifact remains the existing compatible tree. `distribution_snapshot(policy, root)` passively obtains candidate inputs; `build_wheel(result, capture, root, destination)` derives the wheel. `validate_distribution_policy`, `validate_evidence` and `validate_installed_receipt` validate closed data. Project `_distribution_check_freshness` and `_distribution_prepublish(result, snapshot, policy, root, capture)` recheck current inputs before publication; the latter is the narrow supported outside-controller mutation seam. None is a runtime loader/registry.

The [example](../../examples/distribution/README.md) publishes Invoice/status and three functions, installs normally, then checks/builds a separate consumer and calls through stock Python. Wheel guards occupy `checked_pricing._pyalamode_exports.core`; originals remain normal imports. Tree aliases retain their existing namespace. Actual authored order controls parameters, record fields and variant cases, including nonalphabetical declarations; canonical JSON map sorting has no order authority.

## Evidence and passive ownership

The exact schema-1 envelope is `{schema,kind,payload,sha256}`, kind `pyalamode-checked-distribution`. Payload is `{identity,target,producer,inputs,modules,exports,guards,artifacts,claim_scope}`. It carries producer-original absolute paths as informational provenance, relative authored source locations, retained original bytes, installed runtime/debug/facade byte identities, transitive assumptions and distinct module initialization/setup evidence. Input source rows are relative path→`{sha256,module,ownership,shipped,participating}`; selection is an exact module-mode bool map. Consumer export rows contain freshly derived actual contracts, not copied producer proof.

`validate_evidence` has exact finite branches for every envelope/payload/input/module/artifact subtree. `_contract` dispatches function/record/variant shapes; `_callable`, `_schema`, `_setup`, `_guard_export`, `_debug_row`, `_file_row`, `_diagnostic` and `dependency_context` validate nested values. Standard/codec operation rows equal their current detached catalogs. External rows have exact current catalog plus freshness/installed-identity keys, conservative effect/failure expansion, recomputed contract digest and closed M8 provenance/approval/native identities. Project `_distribution_contract_relation` compares current actual declaration/call/schema/row relationships while normalizing producer-original and installed paths through canonical module namespaces. `_finish_distributions` derives actual original/debug/facade bytes, exact generated path inventory, current initialization/setup and debug coverage. A forged checksum/RECORD cannot establish source semantics.

Passive discovery inspects physical directories from the project root and current `sys.path` without finder/path-hook execution. Bounded normalized declared-name dist-info prefixes identify relevant owners before metadata reads; unrelated distributions are ignored. Relevant malformed names, duplicate owners/versions, namespaces, package/module/native/sourceless shadows, symlink parents and ownership escapes refuse. Name/Version/WHEEL/RECORD/evidence identities agree. RECORD digests/sizes are independently checked; only its own row, supported cache rows and fixed installer-added files are distinguished from wheel claims.

Present relevant caches have supported current magic/16-byte header and raw payload equal to one of two exact current compiler recipes: temporary inline `marshal.dumps(compile(...))` first, then a helper-local retained compiled code object if needed. Source/path/runtime/optimization (0/1/2) are actual current inputs; the retained object is released before another candidate or cache entry. At most two compiler/marshal constructions occur per cache. Input caches are never unmarshalled. Absent caches are valid. Unknown/sourceless/mismatched caches refuse tooling2. Legitimate caches compiled for a different installed path can refuse; unchanged source can be recompiled or caches removed. A later valid cache or source change refuses PAL372/1 before publication.

Limits are 64 declarations, 64 top-level packages per declaration, 4096 exports, 16,384 inventory rows, 1MiB per source/metadata/policy/cache file, 16MiB JSON, 64MiB total source/wheel, depth64 and 500,000 JSON nodes. Nominal identities are bounded to 1024 code points, fields/cases to128 before further processing. Reads validate parents first, use bounded reads and pre/post stat consistency. Package count/cumulative bytes and canonical output bytes are bounded while accumulating. Wheels use deterministic uncompressed ZIP metadata and exclusive fresh publication. Prior artifacts are preserved. These are cooperative filesystem/runtime assumptions, not hostile-process isolation.

## Intrinsic reconstruction and current consumer authority

For declaration and generated-byte validation, project constructs at most one fresh strict `_IntrinsicSourceGraph` per check from a deep-detached copy of ALL captured installed sources, owners, canonical names/resolution, aliases, published selectors and required selection, using the same current consumer policy and integration snapshot. It excludes project-owned consumer source, retains installed-owned writers, recomputes ordinary static dependencies, and analyzes without body-cache reuse, filesystem rediscovery, imports, publication or shared mutable results. This graph reconstructs source-derived signature/record/domain schemas, actual declaration order and inferred Assign/AnnAssign/constructor guard rows; producer dictionaries never supply missing facts. Basic declaration keys remain compared unconditionally; full contract and initialization/setup comparisons apply when that intrinsic analyzer succeeds. A stricter current policy refusal alone does not turn intact inputs into tooling2. Original/debug/facade byte comparisons stay exact, including under consumer writer refusal.

The current combined consumer graph ALONE sets semantic source status, diagnostics, failures/effects/trust, accepted exports and consumer proof. Intact inputs plus an analyzed consumer record/module writer remain input0/source1/complete/unverified/exports[], with owned PAL371 and real upstream PAL240, strict build1/noartifact; independently valid unrelated project-owned functions retain their proof. There is no partial installed-export certification from intrinsic facts. Its private `_intrinsic_schema_outputs` marker defaults false on ordinary graphs and cannot be set by policy or metadata. Only the private graph may retain an exact fixed native catalog output schema after denied admission, preserving PAL350/denied approval and all exact argument, definition/setup and dependency-writer gates, so debug locals inferred from an operation can be reconstructed. It never invokes the operation, inherits producer approval or grants current permission. This extra finite installed-closure analysis runs even on warm checks and has separately reported counters.

Canonical import and writer identity is shared by caller analysis and the closed writer scan. Explicit installed resolution wins, then actual initialized local package-before-module resolution, then captured graph aliases. `from package import child` can resolve a captured child only for a captured __init__.py parent with the name absent from BOTH symbols/global_writes and no wildcard write; ordinary def/class/compound/star bindings retain precedence. For an absent generated guard parent, import-from fallback instead requires an exact validated alias and its original mapped to the SAME captured analyzer. `_module_writer_targets` preserves existing real-module behavior; an absent namespace yields only validated captured alias descendants with that same original identity. Writes such as `from checked_pricing._pyalamode_exports import core; core.quote=...` and `import checked_pricing._pyalamode_exports as guards; guards.core=0` invalidate actual declarations and exact alias namespace/cache contexts. An arbitrary dotted child without the validated alias supplies no fallback. No generated parent analyzer, guessed namespace, import hook or synthetic initialization/approval proof is created. Consumed stable reexports use the actual declaration's distribution owner and publication inventory; ordinary/absent installed callables receive owned PAL371 before stability would discard that identity.
