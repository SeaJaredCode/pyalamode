# M6 ordinary runtime contract

Status: runtime implementation and corrected frozen two-platform verification complete. Thirty focused tests pass on actual native and Docker CPython 3.13.1. All artifact trials were repeated after the static family-dependency correction, with current/unchanged/cross-platform product and owned maps. The [measurement report](m06-runtime-measurements.md) and platform JSON retain the current evidence. Root owns independent full-suite/review/CLI acceptance and Git.

The new runtime is original product code in `pyalamode/variants.py` and `pyalamode/failures.py`, with finite data-schema hooks in records, collections and boundaries. It adds no dependency, special loader, exception rewrite, callable purity registry or application evaluation during source checking/building. Stock CPython 3.13.1 supplies ordinary classes, slots, pattern matching and builtin exceptions under its existing licenses. Metadata catalogs describe exact data classes, not callable purity.

## Closed declarations and schemas

`@case` accepts an exact ordinary class containing only public typed fields with stable trailing defaults, optional documentation, or no payload. The M4 closed data annotation parser resolves actual bindings and parses future annotation strings without eval, get_type_hints, arbitrary user subscriptions or descriptors. Bases, custom metaclasses, methods, hooks, untyped values, annotation proxies and mutable defaults fail. `@variant` accepts an exact ordinary class containing only one or more uniquely named nested product case declarations and optional documentation. It replaces that declaration with a closed namespace; the namespace cannot be instantiated or subclassed. Unattached `@case` declarations are not stable data or usable constructors until attached to their declaring domain. Reusing a case in another domain is unsupported.

Generated case classes have exact slot storage, fixed positional/explicit keyword constructor fields, trailing stable defaults and native `__match_args__` in declaration order. Constructors deeply validate every payload before storing it, refuse duplicates/unknown fields/missing fields, and reject reinitialization. Case instances have no dictionary, refuse ordinary assignment/deletion/subclassing, and are unhashable. CPython binds **kwargs before entering the constructor and can consult str-subclass keyword hashes/equality at that stage; the product rejects those keys without adding any further foreign calls, measured against an ordinary function of the same signature. Equivalence includes exact case identity and recursively exact type-sensitive payload equivalence; bool and int are distinct. Representation traverses only admitted data in declaration order. Native pattern matching uses those fixed classes, match arguments and slots; it adds no custom matcher/getter. Unchecked changes to source/product class methods, descriptors, metadata or native reflection remain conditional dependency assumptions, not isolation from hostile Python.

`Option[T]` has exact `Some(value)` and `Nothing()` cases; `Result[T,E]` has exact `Ok(value)` and `Err(error)` cases. Their GenericAlias schemas accept only recursively admitted data arguments. Runtime constructors erase generic arguments but deeply validate stable payloads. Boundary schemas additionally enforce T/E. Capabilities, callbacks, raw exceptions, foreign subclasses, proxies and mutable nested values are excluded. Builtin case classes support the corresponding one-argument annotation aliases, except Nothing which is payload-free. Bare generic family annotations and bare payload cases do not establish a concrete data schema.

The finite wire vocabulary is `('variant', DomainClass, ((CaseClass, fields), ...))`, `('case', CaseClass, fields)`, `('Option', (T,))`, `('Result', (T,E))`, `('Some',(T,))`, `('Nothing',())`, `('Ok',(T,))`, and `('Err',(E,))`. Fields are ordered `(exact_name, schema)` tuples. Failure uses the existing `('record', Failure, fields)` form. Metadata validation establishes exact known class identities before schema comparison, so foreign type hashing/equality/getters are not consulted.

## Operations, effects and failures

| Operation | Valid input and result | Effects and known invocation failures |
| --- | --- | --- |
| User case construction | Fixed deeply typed payloads/defaults; fresh immutable exact case | No ambient effect; recursive validation/allocation can reach RecursionError |
| Some/Nothing/Ok/Err | Deep stable data; fresh exact tagged value | No ambient effect; recursive validation/allocation can reach RecursionError |
| `accumulate(left,right)` | Two exact Ok/Err values; Ok((left.value,right.value)) or Err(Vector errors in left-to-right order) | No additional effects or callbacks; retains ordinary argument computation effects; RecursionError |
| `failure_value(exception)` | Published exact builtin class; fresh Failure with fixed category/message | No ambient effect, exception payload or formatting; RecursionError through immutable construction |
| Structural equivalence/representation | Exact admitted tag and stable payloads | Existing recursive data costs; representation may reach the inherited int formatting ValueError |
| `validate_data(value,schema)` | Known complete schema; returns same validated value | Ordinary optional data guard; invalid inputs TypeError, recursive depth RecursionError |
| `freeze` / `thaw` | Existing ordinary shell contracts plus exact cases | Preserve their ordinary-shell classification and ownership assumptions; no new arbitrary input license |

Ordinary invalid inputs fail TypeError; immutable writes/reinitialization fail AttributeError and subclassing fails TypeError. Those failures do not make an invalid input satisfy an admitted call. Resource exhaustion, interruption and divergence are outside the finite domain-failure claim. Failure handling preserves every IO/State/Clock/Random/Environment effect already performed. `accumulate` invokes no callbacks: Python evaluates both arguments in order before this binary operation. Two errors are retained independently in left-to-right order. Repeated accumulation makes vector-valued errors visible rather than flattening them.

## Exact native failure conversion

`Failure` is an ordinary immutable product record with exact `category: str` and `message: str`. Direct construction is data construction, not evidence an exception occurred. `failure_value` observes only `type(exception)` and compares class identities. It never reads `args`, attributes, dictionaries, traceback, frames, getters, repr/str or exception formatting. Returned records share no mutable exception state. Fixed category messages are ZeroDivisionError: `division by zero`; IndexError: `index out of range`; KeyError: `key not found`; ValueError: `invalid value`; RecursionError: `recursion limit reached`; RuntimeError: `runtime operation failed`; OSError: `operating system operation failed`; UnicodeError: `unicode operation failed`.

The exact accepted identities are ZeroDivisionError, IndexError, KeyError, ValueError, RecursionError, RuntimeError, OSError, UnicodeError; UnicodeDecodeError, UnicodeEncodeError and UnicodeTranslateError map to UnicodeError; BlockingIOError, ChildProcessError, ConnectionError, BrokenPipeError, ConnectionAbortedError, ConnectionRefusedError, ConnectionResetError, FileExistsError, FileNotFoundError, InterruptedError, IsADirectoryError, NotADirectoryError, PermissionError, ProcessLookupError and TimeoutError map to OSError. IOError and EnvironmentError are the same OSError identity. No custom subclass, broad Exception/BaseException, StopIteration, TypeError or arbitrary foreign object is accepted. Unsupported conversion fails TypeError without reading the object.

Python except retains its actual subclass semantics: a RuntimeError handler catches RecursionError, and ValueError catches UnicodeError. Conversion preserves those more precise categories. A checked exception token is handler-local, usable only as the direct failure_value input, and remains a real mutable exception at runtime. The checker refuses escape, alias, reflection, capture, rebind and post-handler use. Static known-failure evidence is conditional on the approved builtin operation/dependency universe producing the published exact native exceptions; ordinary custom exceptions/subclasses violate that input obligation even when ordinary Python except catches them. This is not universal success for every subclass.

## Data integration and exports

Collections and records recursively accept known exact cases. Map/set keys remain the existing exact scalar vocabulary. Variant payload reconstruction is explicit; record replace does not accept cases. Cases are safe to retain across versions and capture as stable data. Raw exceptions and capabilities remain excluded at every depth.

Freeze deeply validates a known case and may reuse it. Thaw exports each occurrence independently into fresh ordinary dict/list storage with exact envelope keys `{'variant': domain_identity, 'case': case_name, 'fields': fresh_field_dict}`. The domain identity is the declaring module plus `:` plus qualified domain name; builtin domains use `pyalamode:Option` and `pyalamode:Result`. Ordered fields recursively export fresh containers. Failure follows record field-dict export. There is no decoder, restoration hook, tag-based arbitrary constructor or implicit reconstruction. Optional guards validate the exact current schema/tag/payload without proving callable purity, environment integrity or exclusive ownership.

## Initialization and actual foundations

Product initialization creates fixed classes, immutable tuple metadata, function objects and one builtin Failure record declaration. It performs no application call, capability setup, IO, clock/entropy/environment observation, exception construction or dynamic eval. Application domain declarations run as ordinary module initialization; source checking never runs them. Their actual declaration and unchanged runtime/source bindings are separate obligations from checked function invocation.

The new modules directly read builtin type/object, tuple/dict/set/str, len/any/next/enumerate/zip/id, classmethod, AttributeError/TypeError and the exact 26 named native exception identities; types.GenericAlias and GetSetDescriptorType. Exact type/object slot/metadata operations, tuple/list/dict/set/string operations and import/class creation are ordinary native foundations. Through records the paths also read types.ModuleType, sys.modules, ast.parse and the finite ast Constant/Name/Subscript/Tuple/Attribute node classes; ast.parse reads builtin compile with PyCF_ONLY_AST and its finite standard parser setup. Existing collection traversal, validation, equivalence and representations retain their full COLLECTION_FOUNDATIONS. Existing record parsing/validation and ordinary snapshots retain RECORD_FOUNDATIONS; adapter generation stays the existing ordinary shell path, not a new variant operation. Schema validation/equality/representation uses the full existing collection/record foundations and the disclosed snapshot data path. Fixed generated __init__/__eq__/__repr__/immutability closures and private catalogs/helpers are product dependencies. Native CPython MATCH_CLASS uses its native instance/class checks, the fixed __match_args__ tuple and fixed member descriptors under the exact unchanged class contract; no foreign matcher is executed for admitted exact cases. Source writer gates must cover all imported private helpers/classes/method aliases and catalogs, not only public decorators. Product/module gates can conservatively invalidate more than one precise operation; that does not admit calling unknown helpers.

No installed backend or licensing addition is introduced. The tuple/slot implementation is dependency-free original code; CPython and standard-library foundations retain their existing licenses.

## Source costs and measurement limits

Let c be the count of registered case classes, d the number of registered domains, f fields in a case, and n the total traversed payload nodes. Identity metadata lookup scans tuple catalogs in O(c+d); construction/validation traverses payloads with nested catalog scans. Constructor keyword membership can take O(f²), and generated instances store O(f) references. Deep validation tracks active identities, rejects cycles and has recursion-depth limits. Equality and representation recursively traverse payloads and preserve ordered field semantics. A case declaration parses finite field schemas/defaults, scans its complete module annotation namespace and copies the growing case metadata tuple. Sealing k cases examines c catalog entries against those k identities, taking O(ck) work plus metadata copies. Declarations are ordinary setup excluded from invocation timing.

Binary accumulation validates both inputs and constructs a pair or vector with at most two error references; total cost includes recursive input/output validation and catalog scans, not only the fixed branch count. No callbacks or error formatting occur. Failure conversion scans a fixed finite native-class tuple and constructs two exact strings in a fresh record. Freeze validation is recursive; thaw allocates independent nested export containers for every occurrence, so repeated aliases expand into separate copies.

The frozen [measurement report](m06-runtime-measurements.md) publishes actual checked off/exports/debug artifact observations: six workloads at n=10/100, three trials of 25 calls, 36 rows/108 intervals/2,700 measured calls plus 360 warmups per platform. All twelve product and eight owned source SHA maps are unchanged/current/equal across platforms. Inputs, setup/build/import/counting/warmups and correctness checks are outside intervals; tracemalloc is included and memory is not RSS. Human authoring benefit, general application latency and speedup remain unmeasured.
